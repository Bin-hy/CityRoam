# TripPilot v1.3 用户区分与 OIDC 登录 Spec

状态：待审批（spec）
日期：2026-11-20

## 背景

- 现状是单租户 demo：`trips` 无归属字段，任何拿到 ID 的人都能读写；唯一的管理员保护是 eval 的 `ADMIN_TOKEN`。
- 目标是在不改变 demo 定位的前提下：支持区分用户、支持 OIDC 登录、支持用开关启用/停用；LLM、AMap、插件等 API Key 继续由服务端全局配置，不做用户维度。
- yufu 作为本地验收用的 OIDC IdP；接入按通用 OIDC 实现，不绑定 yufu SDK。认证由 IdP 负责，授权由 TripPilot 自己负责（本地 RBAC）。

## 术语

- **匿名 demo 模式**：`AUTH_ENABLED=false`，不需要登录，保持当前所有行程共享的行为。
- **归属**：每个行程属于一个本地用户；登录用户只能访问自己的行程。
- **本地用户**：以 IdP 的 `issuer + subject` 唯一标识，本地存角色和展示资料，不存密码。
- **本地 RBAC**：TripPilot 自己维护 `user/admin` 角色；IdP 只提供身份，不提供授权。
- **服务端会话**：IdP token 只在 Go 服务端使用，浏览器只持不可猜测的会话 Cookie。

## 目标

- G1：一个开关控制认证启停；关闭时完全保持现有 demo 行为。
- G2：开启后通过通用 OIDC（授权码 + PKCE）登录，服务端会话，浏览器不接触 token。
- G3：行程按用户隔离，并提供「我的行程」列表；他人行程不可见。
- G4：本地 `user/admin` 角色；admin 可访问 eval，普通用户不可；现有 `ADMIN_TOKEN` 继续保留给脚本/应急。
- G5：API Key、模型、插件凭据保持全局，所有登录用户共享；分享页保持免登录公开。

## 功能需求

### A. 开关与 OIDC 登录

- **F1 开关关闭**：`AUTH_ENABLED=false` 时不需要登录，行程 API 保持当前行为；前端不显示登录入口、用户菜单和「我的行程」区块；eval 仍由 `ADMIN_TOKEN` 保护；`/api/auth/me` 返回 `enabled=false`，便于前端判断。
- **F2 开关开启后的门槛**：`AUTH_ENABLED=true` 时，创建、查询、调整、重规划、恢复版本、删除、创建分享等行程能力都要求登录；未登录返回统一 401 错误码 `unauthorized`；前端跳转登录页并保留原始路径。健康检查、`/api/meta`、分享读取、`/api/auth/*` 保持公开。
- **F3 OIDC 配置**：启用时必需 `ISSUER`、`CLIENT_ID`、`CLIENT_SECRET`、`REDIRECT_URI`；可选 `SCOPES`（默认 `openid profile email`）、`AUDIENCE`、登录按钮显示名、注销后跳转地址。启用但配置缺失或 discovery 失败时，启动即失败并给出可执行错误；关闭时完全不校验 OIDC 配置。
- **F4 登录流程**：采用授权码 + PKCE，校验 `state`（一次性）与 `nonce`；回调先兑换 code，再校验 ID Token，配置 `AUDIENCE` 时校验 access token，再读取用户资料；成功后建立本地会话并回到经过校验的 `return_to`（仅允许站内相对路径，默认 `/`）。失败时不暴露 token，登录页显示可读原因。
- **F5 服务端会话**：浏览器只持不可猜测的随机会话 ID（HttpOnly、SameSite=Lax、HTTPS 下 Secure）；会话存服务端并有过期时间；未知或过期会话视为未登录。退出时删除服务端会话并清 Cookie；配置了 IdP 注销端点时可先跳转 IdP 注销。不保存 refresh token，不把任何 IdP token 下发给浏览器。
- **F6 当前用户接口**：公开的 `GET /api/auth/me` 返回是否启用、是否已登录、用户 ID、邮箱、名称和角色；提供登录跳转、回调和退出接口。响应禁止缓存。

### B. 本地用户与授权

- **F7 本地用户**：以 `issuer + subject` 唯一识别用户，首次登录自动创建本地记录，之后登录刷新邮箱、名称等展示资料；邮箱不是主键，不作为唯一身份。
- **F8 行程归属隔离**：行程记录归属一个本地用户；创建时自动归属当前用户；查询、变更、版本、分享创建都要求当前用户是所有者，非所有者按 `404` 处理（不暴露“存在但无权限”）。运行、版本、证据等通过所属行程间接鉴权。幂等重放只返回自己的行程；同一幂等键被其他用户占用时返回冲突，不泄露他人行程。
- **F9 我的行程**：新增当前用户的行程列表，按创建时间倒序，支持分页；返回状态、最近版本等摘要。认证开启时首页展示「我的行程」与空状态；认证关闭时前端不展示该区块。
- **F10 本地 RBAC**：用户角色为 `user`（默认）或 `admin`；通过服务端环境变量白名单（邮箱或 `issuer+subject`）在每次登录时同步角色。`admin` 才能访问 eval 用例、运行和看板；普通用户返回 `403`；`ADMIN_TOKEN` 继续作为脚本/应急凭据被接受。角色变化记录审计日志。
- **F11 存量无主数据**：`owner_id` 允许为空。认证开启后，无主行程不进入任何用户的「我的行程」，也不能被访问；认证关闭时仍按现状可见可用；不自动猜测归属、不删除数据。
- **F12 全局 API Key**：LLM、AMap、酒店/攻略插件凭据继续由服务端环境变量提供；不新增用户维度的 Key、模型选择或配额接口、字段和 UI；所有登录用户共享同一套服务端配置。
- **F13 限流口径**：认证关闭时沿用按 IP 限流；认证开启时按已登录用户限流，未认证的公开接口仍按 IP。每小时额度沿用现有配置。

### C. 前端与部署

- **F14 登录界面**：独立的登录页，展示 IdP 登录按钮、错误信息和返回路径；登录后顶部显示用户名与退出入口；受保护路由未登录时跳转登录页，登录后回到原路径。
- **F15 分享不受影响**：分享页与分享读取接口始终免登录；认证开启时，只有行程所有者能创建分享链接。
- **F16 分离部署**：支持通过 CORS 白名单和浏览器带凭据的请求访问 API；会话仍为 Cookie 模式，不增加浏览器保存 token 的模式。同源部署（Caddy 反代）保持默认且无需额外配置。
- **F17 eval 前端**：管理员登录后可免 token 使用 eval 看板；未登录或非管理员仍可使用现有 `ADMIN_TOKEN` 输入框，非管理员登录身份被明确拒绝。

## 非功能需求

- **N1 安全**：IdP token 不下发浏览器；PKCE 使用 S256，`state`/`nonce` 一次性校验；ID Token 校验签发方、受众、有效期与 nonce；会话 ID 不可猜测；Cookie 为 HttpOnly，HTTPS 下 Secure；认证开启时对非 GET 请求做 Origin/Referer 校验（SameSite=Lax 之外的第二道防线）；`return_to` 只接受站内相对路径，防开放重定向；`ADMIN_TOKEN` 比较保持常量时间；日志不输出 token、Cookie、client secret，用户标识只记录内部 ID 或 `sub` 摘要。
- **N2 配置与失败方式**：认证关闭时完全忽略 OIDC 配置；开启时配置缺失或发现失败在启动阶段报错，错误信息说明缺哪个变量或哪个端点不可达；`.env.example` 与环境变量文档同步更新。
- **N3 兼容性**：认证关闭时，v1/v1.1 的 API 行为、SSE、分享、eval、20 条评测基线保持不变；数据库变更为增量迁移，现有数据不重写；前端在两种模式下都能构建和运行。
- **N4 可靠性与数据**：会话表按过期时间建索引，过期会话可被惰性拒绝并定期清理；迁移有可执行的 down；登录回调可安全重试（state 一次性，重复回调返回明确错误）。
- **N5 可观测性**：结构化日志记录登录成功/失败、退出、角色同步和鉴权拒绝，带 `request_id` 与内部用户 ID；不新增指标系统，沿用现有 `log/slog`。
- **N6 部署**：同源部署保持默认；分离部署通过 CORS 白名单和 `credentials: include` 适配；HTTPS 下 Cookie 带 Secure，需正确传递 `X-Forwarded-Proto`；演示环境可额外启动 yufu，但生产构建不依赖 yufu 专有实现。
- **N7 性能**：每个已认证请求只增加一次带索引的会话查询（必要时一次用户查询）；不改变 Agent、SSE 和插件调用链路及延迟特征。
- **N8 可测试性**：会话、认证中间件、角色判断和归属校验有单元测试；OIDC 回调可用假 IdP/httptest 做集成测试；yufu 真实登录作为人工验收项。

## 不做的事

- 不做密码、注册、找回密码、MFA，均由 IdP 负责。
- 不做用户维度的 API Key、模型选择、配额或计费。
- 不做多 IdP 选择器、个人资料编辑、账号注销、用户管理后台。
- 不做团队协作、多人共享编辑或 owner 之外的细粒度权限。
- 不允许 admin 查看其他用户的行程。
- 不做浏览器保存 token 的模式，不保存 refresh token，不向浏览器转发 IdP token。
- 不做 back-channel logout、跨设备会话管理；只做本地会话注销，外加可选的 IdP 注销跳转。
- 不迁移、不删除现有匿名行程的归属。
- 不改变分享页的公开语义，不改变 eval 指标与跑批逻辑。

## 验收标准

- **AC1（F1）** 认证关闭：未登录可创建、查看、调整行程；前端无登录入口；`/api/auth/me` 返回 `enabled=false`；eval 用 `ADMIN_TOKEN` 正常访问。
- **AC2（F2）** 认证开启：未登录调用创建/查询行程返回 401 `unauthorized`；`/healthz`、`/api/meta`、`/api/share/{slug}`、`/api/auth/*` 仍可公开访问。
- **AC3（F3）** 认证开启但缺少必需 OIDC 配置或 discovery 失败时，启动失败且错误指明变量或端点；认证关闭时同一份无效 OIDC 配置不影响启动。
- **AC4（F4）** 使用 yufu 完成登录后建立会话并回到原页面；篡改/重放 `state` 或使用外部 `return_to` 被拒绝，不发生跳转。
- **AC5（F5/F6）** 登录后 `/api/auth/me` 返回当前用户；会话 Cookie 为 HttpOnly；退出后旧 Cookie 再访问返回 401；伪造或过期会话同样 401。
- **AC6（F7）** 同一 `issuer+subject` 重复登录只对应一个本地用户；邮箱变化不会产生新用户。
- **AC7（F8）** 用户 A 的行程，用户 B 查询、变更或创建分享均返回 404；A 正常可用；跨用户复用幂等键返回冲突且不泄露 A 的行程。
- **AC8（F9）** 行程列表只包含当前用户行程，按创建时间倒序、分页正确；无数据时有空状态。
- **AC9（F10/F17）** 白名单管理员登录后可直接打开 `/eval` 并调用 eval 接口；普通用户返回 403；未登录仍可用 `ADMIN_TOKEN` 访问；角色变化有日志。
- **AC10（F11）** 认证开启时无主旧行程不可见且按 404 处理；认证关闭时仍可访问。
- **AC11（F12）** 数据库与 API 不出现用户维度 Key/模型字段；两个用户使用同一套服务端 Key 均能正常生成行程。
- **AC12（F13）** 认证开启时两个用户各自拥有独立的小时额度；认证关闭时仍按 IP 共享额度。
- **AC13（F14）** 未登录访问受保护前端路由会跳转登录页；登录后回到原路径；顶部显示用户名并可见退出入口。
- **AC14（F15）** 认证开启时，未登录浏览器打开分享链接仍能看到行程；非所有者创建分享被拒绝。
- **AC15（F16）** 配置 CORS 白名单后，分离部署的前端带凭据完成登录和 API 调用；浏览器存储中没有 IdP token。
- **AC16（N1）** 日志与错误响应不含 token、Cookie、client secret；非白名单来源的跨站写请求被拒绝；`ADMIN_TOKEN` 比较为常量时间。
- **AC17（N3/N4）** 认证关闭时既有测试与 v1/插件评测基线通过；迁移可 up/down；重复回调被明确拒绝。
