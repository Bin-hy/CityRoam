## 开关与公开面

- [x] 认证关闭时，未登录用户可以创建、查看、调整行程（验证：不登录调用创建接口返回 202，打开工作台正常展示）。
- [x] 认证关闭时，前端没有登录入口、用户菜单和「我的行程」区块（验证：浏览器打开首页观察）。
- [x] 认证关闭时，`GET /api/auth/me` 返回 `enabled=false` 且 `authenticated=false`（验证：curl 查看响应）。
- [x] 认证开启时，未登录调用行程创建/查询返回 401，错误码为 `unauthorized`（验证：curl 不带 Cookie）。
- [x] 认证开启时，健康检查、`/api/meta`、`/api/share/{slug}`、`/api/auth/*` 仍可公开访问（验证：curl 逐项请求）。
- [x] 认证开启但缺少必需 OIDC 配置或 discovery 失败时，API 启动失败且错误指出变量或端点（验证：启动进程观察退出与错误文本）。
- [x] 认证关闭时，同一份无效 OIDC 配置不影响启动（验证：设置错误 issuer 后启动成功）。

## 登录、会话与用户

- [x] 使用本地 yufu 完成登录后回到原路径，`/api/auth/me` 返回稳定的用户标识与角色（验证：浏览器登录后查看 me 响应）。
- [x] 会话 Cookie 为 HttpOnly，浏览器 JS 无法读取；浏览器存储中不存在 IdP access/ID token（验证：DevTools Application 面板）。
- [x] 退出后旧 Cookie 再访问受保护接口返回 401（验证：保留旧 Cookie 重放请求）。
- [x] 伪造或过期的会话 Cookie 返回 401（验证：篡改 Cookie 值或等待过期后请求）。
- [x] 篡改 `state`、重放已消费的回调、绑定 Cookie 不匹配均被拒绝，不发生登录（验证：构造回调请求观察错误与未建立会话）。
- [x] 外部 `return_to`（绝对 URL、`//` 开头、含反斜杠）被拒绝且返回 400 `invalid_return_to`，不发生开放重定向（验证：请求登录接口观察响应与 Location）。
- [x] 同一 `issuer+subject` 重复登录只对应一个本地用户；邮箱变化不会创建第二个用户（验证：在 IdP 改资料后重新登录，对比 me 的用户 ID）。
- [x] 角色变更后无需重新登录即可生效（验证：调整白名单后，新请求的 eval 权限随数据库角色变化）。

## 归属与列表

- [x] 用户 A 创建的行程，用户 B 查询、删除、调整、创建分享均返回 404（验证：两个账号分别请求）。
- [x] 用户 B 的「我的行程」不包含 A 的行程（验证：对比两人列表）。
- [x] 用户 A 的 run 事件流、resume、cancel 对 B 返回 404（验证：用 A 的 run ID 以 B 身份请求）。
- [x] 跨用户复用同一幂等键返回 409 `request_id_conflict`，响应不包含他人 trip ID（验证：两人用相同 `client_request_id` 创建）。
- [x] 「我的行程」只包含当前用户行程，按创建时间倒序，分页参数生效（验证：创建多条后翻页对比）。
- [x] 无行程时列表显示空状态，不显示错误（验证：新用户登录后打开首页；`MyTripList.test.tsx` 断言「还没有行程」）。
- [x] 认证关闭时创建的无主旧行程，在认证开启后不可见且按 404 处理；关闭后仍可访问（验证：切换开关前后访问同一 trip ID）。
- [x] 认证关闭时 `GET /api/trips` 返回 200，且只包含 `owner_id IS NULL` 的行程摘要（验证：无 Cookie 请求并核对返回项）。

## 授权与管理员

- [x] 白名单管理员登录后可直接打开 `/eval` 并调用 eval 接口，无需输入 token（验证：管理员账号操作看板）。
- [x] 已登录普通用户访问 eval 返回 403 `forbidden`，前端显示需要管理员角色（验证：普通账号访问 `/eval` 与接口）。
- [x] 未登录或不使用会话时，`ADMIN_TOKEN` 仍能访问 eval 接口（验证：curl 带 `X-Admin-Token`）。
- [x] 角色同步日志包含用户内部 ID 与 `from/to`，不包含 token 或 secret（验证：查看结构化日志）。
- [x] admin 不能查看其他用户的行程（验证：管理员访问普通用户 trip ID 返回 404）。

## 全局配置与限流

- [x] 数据库与 API 中没有用户维度的模型 Key、提供商 Key 或配额字段（验证：检查表结构与 OpenAPI）。
- [x] 两个不同用户都能使用同一套服务端 LLM/AMap/插件配置生成行程（验证：两个账号各创建一次）。
- [x] 认证开启时两个用户的每小时额度相互独立（验证：用户 A 打满后用户 B 仍可创建；观察 429 归属）。
- [x] 认证关闭时仍按 IP 共享额度（验证：同一 IP 连续创建触发 429，换 IP 不受影响）。

## 前端与部署

- [x] 认证开启时，未登录访问 `/` 或 `/trips/:id` 会跳转登录页，登录后回到原路径（验证：浏览器操作）。
- [x] 顶栏显示用户名，退出后回到首页且受保护页面重新要求登录（验证：浏览器操作）。
- [x] 会话在使用中失效时，工作台给出“会话已过期”与重新登录入口，而不是空白页（验证：删除或篡改 Cookie 后刷新工作台。实际观察为 AuthGate 整页跳转 `/login?return_to=…`，同样提供重新登录入口；工作台内联卡片未在自动化中触发）。
- [x] 认证开启时，未登录浏览器（隐身窗口）打开分享链接仍能看到行程（验证：复制分享链接到隐身窗口）。
- [x] 非所有者创建分享链接返回 404，不生成链接（验证：B 对 A 的行程请求分享）。
- [x] 配置 CORS 白名单后，分离部署的前端带凭据完成登录和 API 调用（验证：不同源启动静态站点访问 API。已用 `Origin: http://localhost:5175` 校验预检与响应头，并经 5175 前端完整登录；未额外搭独立静态站点直连）。
- [x] 未配置 CORS 时，同源部署无需额外配置即可登录和使用（验证：Caddy/Vite 代理模式）。

## 端到端场景

- [x] 场景 1（认证关闭）：打开首页 → 输入需求 → 创建行程 → 事件流推进 → 接受方案 → 分享链接可打开（预期：与现有 demo 行为一致）。
- [x] 场景 2（认证开启，双用户隔离）：用户 A 登录 → 创建行程 → 在「我的行程」看到 → 退出 → 用户 B 登录 → 列表无 A 的行程 → 用 A 的链接访问得到 404（预期：隔离成立）。
- [x] 场景 3（认证开启，公开分享）：A 登录并分享已接受方案 → 隐身窗口打开分享链接 → 无需登录可查看（预期：公开可读）。
- [x] 场景 4（认证开启，管理员）：白名单管理员登录 → 打开 `/eval` → 无需 token 查看用例与运行 → 普通用户登录访问得到 403（预期：RBAC 生效）。
- [x] 场景 5（开关回滚）：认证开启运行一段时间后关闭开关 → 旧无主行程恢复可见 → 新访客无需登录即可创建（预期：demo 行为恢复，数据未丢失）。
