# TripPilot v1.5 交互重构 Spec

状态：已批准（spec）
日期：2026-11-20

## 背景

TripPilot 的规划能力已经完整（v1 20/20、插件 8/8），但工作台的交互仍是 PRD 三栏监控面板的直译实现，存在四个结构性问题：

- **Agent 没有叙述**：用户看到的是带 `#seq` 的技术事件，不是 Agent 在沟通。
- **推理被浪费**：后端已生成逐 POI 的 `explanations`，前端模型直接丢弃，用户看不到「为什么选它」。
- **插件不可见**：工具调用只有「名称 + 耗时 + 条数」，没有查询、参数与结果；研究结果只在事后以文本面板出现，与方案脱节。
- **界面没有主角**：所有模块都是等权卡片；主操作卡随状态整卡替换（补信息 → 选酒店 → 确认 → 调整），位置反复跳变；移动端退化为长滚动。

本次为 v1.5 交互重构：让 Agent 成为对话主体、方案成为画布、推理与工具过程可见，并把全站统一为一套「旅行编辑感」的设计语言。

## 目标

- **G1 Agent 成为对话主体**：工作台左侧是连续对话流，包含用户发言、Agent 阶段叙述、工具卡、追问与确认卡、结果卡；状态变化表现为新消息，而不是同一张卡变形。
- **G2 方案成为画布**：地图、时间轴、选中点详情、预算、版本围绕当前方案组织，有明确主次；对话只占一列。
- **G3 推理可见**：每个 POI 的「为什么选它」、攻略提及与来源、校验结果和修复原因，都在对应位置可查。
- **G4 一个输入框贯穿全程**：创建、补信息、拒绝后修改、完成后调整复用同一个输入框，按当前状态决定行为。
- **G5 全站一套语言**：创建页、工作台、分享页、登录、历史列表统一为「旅行编辑感」：少卡片、强排版、留白与分隔线建立层次。
- **G6 确定性、可重放**：不新增 LLM 调用；对话由事件确定性生成，刷新或断线重连后能重建；插件卡数据来自向后兼容的事件字段增补。

## 功能需求

### F1 创建与进入对话

- 创建页以一个自然语言输入框为主入口，示例需求可一键填入。
- 天数、预算、节奏、兴趣、必去、避开、用餐等作为「偏好标签」按需添加，不再展示成片的大表单。
- 提交后立即进入该行程的对话工作台：对话出现用户消息，Agent 开始逐阶段回应；提交失败时错误就地显示且输入不丢失。
- 已登录用户可从历史列表返回任意行程，恢复到最近一次运行的对话；游客模式保持现状。
- 用户可从对话回看本次会话的原始输入与约束解析结果。

### F2 对话流与重建

- 一次运行构成一个「回合」：用户消息 + Agent 阶段消息 + 工具卡 + 决策卡 + 结果卡。
- Agent 消息按阶段聚合（理解需求 / 研究 / 挑选与排程 / 校验 / 修复 / 完成），不逐条罗列技术事件；同一阶段不产生重复消息。
- 阶段叙述由事件确定性地生成，措辞模板化，不新增 LLM 调用；信息不足时不臆造细节。
- 消息顺序由事件序号决定。刷新或断线重连后，对话按已持久化事件重建，不重复、不丢序；重连期间有明确状态提示。
- 对话默认展示当前运行的回合，并保留本次会话的用户输入（含调整指令）；更早的历史由版本入口承载。
- 校验通过/失败、修复轮次、降级原因等以对话语言呈现，并可从消息跳转到画布中对应位置。

### F3 插件 / 工具卡

- 每次工具调用生成一张工具卡：工具名称、人类可读的查询摘要、状态（进行中 / 成功 / 失败 / 缓存命中）、耗时。
- 完成后展示结果数量与至多 3 条结果预览（酒店名称与每晚价格、攻略标题与站点等）。
- 工具卡默认折叠为一行摘要，可展开查看参数摘要、结果预览、重试与缓存标记；失败时说明原因以及是否影响方案。
- 同一回合内同一工具的多次调用按顺序排列，允许逐条展开，不做不可读的合并。
- 研究完成或降级以一条 Agent 消息呈现，包含酒店、攻略匹配数与降级原因。
- 工具未启用或旧运行缺少增补字段时，工具卡降级为「名称 + 状态」，不出现空白或错误。

### F4 追问与确认（全部在对话内）

- **缺信息**：出现「补充信息」卡，仅询问缺失字段；提交后折叠为已补充摘要，Agent 继续。输入框也可直接以文字回答。
- **住宿选择**：出现「选择住宿」卡，列候选名称、地址、价格/晚、评分、预订链接，并提供「不计住宿」；选定后折叠为摘要，地图同步出现住宿锚点。该状态只接受卡片选择。
- **提案确认**：出现「确认卡」，展示摘要、影响与提醒，提供接受 / 拒绝 / 取消；拒绝进入修改输入态，接受生成新版本并折叠为结果摘要。输入框也可直接描述修改，走同一回合的 revise。
- **调整完成**：在已完成行程上提出调整后，产生新的调整回合与提案卡；接受后画布更新，拒绝后在同一回合继续修改。
- 同一时刻最多一张待操作卡处于展开态，已处理卡片只保留摘要；任何状态变化都不再整卡替换原有操作区。

### F5 方案画布

- 画布包含：行程标题与状态、按天切换（全部 / 第 N 天，含日期与当天花费）、地图、时间轴、选中点检查器、预算摘要、版本入口、分享入口。
- **地图**：按天着色的编号标记、住宿标记与路线折线；当前天强调、其他天弱化；点击标记选中该点并同步时间轴与检查器；切换天时地图聚焦该天。
- **时间轴**：按天分组，显示时间、类型（景点 / 餐饮 / 交通 / 休息）、标题与花费；选中与地图双向同步；桌面端可缩放和平移。
- **检查器**：未选中时给出引导；选中后显示时间、时长、花费、交通衔接、「为什么选它」（后端已有的逐点解释）、相关攻略提及与来源链接（若有）。
- 运行中草稿生成时，画布以「草稿预览」呈现并明确标识；最终确认后转为正式版本。
- 对话中的校验/修复消息可定位到画布对应的天或点。

### F6 预算、版本与分享入口

- 预算改为画布工具栏的摘要（总计）；点开可看门票、餐饮、交通、住宿拆分、是否含住宿及其切换、估算提示。切换住宿口径沿用现有行为并产生新的调整回合。
- 版本改为工具栏菜单：版本号、时间、变更原因；选择历史版本可查看与当前版本的差异（新增 / 移动 / 删除在时间轴或检查器中体现）；可回退，回退后对话出现结果消息。
- 分享入口保留现有能力（生成与复制链接），不改变权限模型与快照语义。

### F7 移动端

- 小屏以对话为第一界面：对话流全宽、输入框吸底、顶部提供「查看方案」入口。
- 方案以全屏面板呈现，内含按天切换、地图 / 时间轴切换与检查器；关闭后回到对话原位置。
- 工具卡、确认卡在窄屏下不横向溢出；地图与检查器可独立滚动。

### F8 分享页

- 只读叙事结构：标题区（城市、天数、总预算、AI 生成标识）→ 地图与时间轴 → 选中点详情（含理由与攻略来源）→ 住宿与攻略摘要 → 预算摘要。
- 保持快照只读语义，提供复制文本与「我也来规划一版」入口。
- 不展示运行轨迹、版本操作或内部信息。

### F9 全站视觉与状态

- 统一「旅行编辑感」：米色底、墨绿主色、衬线风格标题、等宽数字；用排版、留白与细分割线建立层级，卡片只用于浮层、决策与工具等需要边界的对象。
- 加载、空、错误、断线状态使用与最终布局一致的骨架或说明，不以无限转圈作为主要进度表达。
- 新消息与状态变化可被读屏感知；键盘可完成选天、选点、展开工具卡与提交输入。
- 创建页、工作台、分享页、登录、历史列表、评测面板使用同一套颜色、字体与间距 token；评测面板仅换皮，功能不变。

### F10 事件增补（向后兼容）

- 工具调用事件增加：人类可读的查询摘要、结果预览（有数量上限）、缓存与重试标记；不新增事件类型，不改变既有字段语义。
- 校验事件增加「已检查项数」或等价信息，用于展示「X 项约束通过」。
- 所有新增字段均为可选；旧事件与旧运行按缺省降级显示；无需数据库迁移。
- 不记录或展示 API Key、供应商原始响应与用户敏感信息。

## 非功能需求

### N1 确定性与可重放

- 对话内容只由「已持久化事件 + 方案/版本数据」推导，相同事件序列必须得到相同对话。
- 刷新、断线重连、重复投递都不得产生重复消息或乱序；事件序号是唯一顺序依据。
- 已完成的用户动作以服务端状态为准；前端不做不可回滚的本地改签。

### N2 性能预算

- SSE 事件到达后界面更新在 100ms 内完成；单条事件不得触发整页重渲染或地图重建。
- 地图选点、切换天、展开工具卡保持流畅（目标 60fps），不因对话增长而退化。
- 不引入重量级依赖；地图与时间轴维持按需加载；首屏新增 JS 增量控制在 50KB（gzip）以内。
- 加载骨架与最终布局尺寸一致，不出现明显跳动。

### N3 可访问性

- 达到 WCAG 2.1 AA：正文对比度 ≥ 4.5:1，大字与图形 ≥ 3:1；焦点可见；所有交互可键盘完成。
- 对话流使用可感知的日志语义，新消息以礼貌方式播报，不打断用户当前操作。
- 支持 200% 文字缩放与减少动态效果偏好；触控目标不小于 44×44。
- 地图信息窗内容必须转义，不渲染未净化的 HTML。

### N4 响应式与移动端

- 覆盖 390 / 768 / 1024 / 1440 宽度；除时间轴内部平移外不出现横向滚动。
- 小屏输入框吸底并避开安全区；方案面板全屏打开后可返回原对话位置。
- 窄屏下工具卡、确认卡、检查器内容可纵向滚动，关键信息不截断。

### N5 兼容性与降级

- 支持最近两个大版本的 Chrome、Edge、Safari、Firefox，以及 iOS Safari 16+。
- 插件全部关闭、研究降级、地图 Key 缺失、旧运行无增补事件、游客模式均能完整使用对话与方案查看。
- 缺失解释、攻略、住宿或价格时，对应区域给出明确说明，不空白、不报错。

### N6 成本与架构约束

- 不新增 LLM 调用；不新增后端服务、消息队列或缓存组件；不新增数据库表或迁移。
- 事件增补为可选字段，预览不超过 3 条、单条事件新增内容不超过约 2KB。
- 继续使用单实例 SSE 与现有部署方式，不要求服务端渲染。

### N7 安全与隐私

- 对话与工具卡只展示分享安全的数据：不回显 API Key、请求头、供应商原始响应、内部堆栈。
- 外部链接只接受 http/https，并以新窗口打开且不传递 opener；事件文本按纯文本渲染。
- 分享页继续只暴露快照允许的字段；新组件不得把内部运行信息带到分享视图。

### N8 可测试性

- 对话推导、阶段聚合、工具卡摘要等核心逻辑为纯函数，可用固定事件样例做单元测试。
- 端到端覆盖：创建 → 对话 → 确认 → 画布 → 调整 → 分享。
- 测试不得依赖真实外部工具或真实 LLM；插件事件用固定样例或 mock SSE 驱动。
- 现有前端测试、类型检查、构建与 Playwright 场景保持通过（允许按新交互更新断言）。

### N9 设计系统一致性

- 颜色、字体、间距、圆角、阴影、动效统一由 token 提供；除 token 文件外不散落硬编码色值。
- 同一信息在不同页面使用同一组件与同一措辞（如「为什么选它」「估算」），不出现同义异形。
- 评测面板只应用视觉 token，不改变信息结构与功能。

### N10 内容与语言

- 界面文案统一为简体中文；金额统一人民币并保留等宽数字；日期与时间使用统一格式（如「11 月 21 日 周六」）。
- 文案避免内部术语泄漏（如 `run_id`、`seq`、`blocking`）；技术细节只在可展开的「详情」中出现。

## 不做的事

- 不改变规划算法：解析、检索、研究、草稿、排程、校验、修复、停止条件的规则不变。
- 不新增城市、POI 数据、天气工具、预订 / 支付 / 库存校验。
- 不做 token 级流式输出、Agent 自主多轮工具探索、长期记忆或个人偏好档案。
- 不引入 assistant-ui、CopilotKit 或新的 UI 框架；不新增浏览器端状态库。
- 不做暗色模式、多语言、PWA / 离线模式。
- 不做多人协作、评论、通知、推送。
- 不改变分享的权限、过期与快照语义；不做打印样式与 PDF 导出。
- 不改数据库结构，不回填历史事件；旧运行按降级规则展示。
- 不重构后端 Graph、Runner 或插件注册机制；只做事件字段增补。
- 不做实时拖拽编辑时间轴、地图聚合 / 热力图、图片与媒体。
- 评测面板不重做交互，仅应用视觉 token。
- 不建设 Storybook 或独立设计系统站点。

| AC2 | 运行中刷新页面，对话按已持久化事件恢复，不重复、不乱序；阶段消息数量与阶段数一致，不逐事件刷屏。 | F2 |

| AC5 | 工具失败或研究降级时，卡片显示原因；方案仍能生成或明确告知影响，界面不报错。 | F3 |
| AC6 | 缺少城市 / 天数时出现补充卡；提交后卡片折叠为摘要，Agent 继续执行。 | F4 |

| AC8 | 接受提案生成新版本并更新画布、对话出现结果消息；拒绝后进入修改输入态，再次提交在同一回合继续并产生新提案。 | F4, F7 |
| AC9 | 点击地图标记或时间轴块，两者与检查器双向同步；检查器显示时间、花费、交通衔接与「为什么选它」；切换天后地图聚焦该天。 | F5 |
