# TripPilot v1.4 天气工具 Spec

状态：待审批（spec）
日期：2026-11-20

## 背景

TripPilot 已具备天气数据能力，但没有进入规划流程：

- 高德天气客户端和软失败包装已存在（`internal/tools/amap.go`、`internal/tools/weather.go`），但 graph 中无任何节点调用，只有测试在使用。
- 天气约束只有 `rain_aware` 布尔值；C11 仅按「当天户外点位占比」发 warning，既不看真实预报，也不触发修复。
- 研究阶段已有工具循环和 governor（超时、重试、TTL 缓存、调用额度、事件），但额度预留在缓存查询之前，缓存命中仍占调用额度，「缓存减少工具调用」目前不成立。
- 已确认的产品方向：天气做成模型可调用的工具；缓存按城市和日期做粒度；雨天户外占比过高时产生阻塞级违规并触发一次修复；无预报时降级为 warning。

## 术语

- **上游查询**：真正向天气数据源发起的请求；缓存命中和运行内去重都不算。
- **缓存命中**：在有效期内复用相同城市与日期范围的历史结果。
- **运行内去重**：同一运行中相同工具与参数只执行一次，后续请求直接复用结果。
- **雨天违规**：预报当天有雨或雪，且该天户外点位占比超过阈值。
- **预报窗口**：数据源实际返回的日期范围；超出窗口的日期视为无预报。
- **降级**：外部依赖不可用、超时或数据为空时，主流程继续，明确缺失原因，不伪造数据。

## 目标

- G1：用户规划行程时，agent 能查询未来天气，并让草案与校验使用真实预报。
- G2：天气查询结果可缓存，缓存命中不消耗单次运行的调用额度。
- G3：同一运行内重复的相同工具请求不重复执行、不重复计数。
- G4：缓存与额度语义对后续新增工具可复用，而不是天气专用特例。

## 功能需求

- **F1 天气查询工具**：agent 在研究阶段可以按城市和日期范围查询逐日预报，获得日期、白天/夜间天气、最高/最低温；结果标注数据来源。城市名不合法或超出预报窗口时返回结构化错误，研究流程继续。
- **F2 工具额度**：天气工具计入本次运行的调用总预算，并单独限制为每次运行最多 1 次上游查询；额度耗尽时向模型返回可读错误，而不是中断运行。
- **F3 结果缓存**：相同城市、相同日期范围的查询在缓存有效期内直接复用结果。缓存键必须包含标准化城市标识和日期范围，不同城市之间不得串数据。有效期可配置，默认 30 分钟。
- **F4 缓存不占额度**：只有真正发起上游请求的调用才消耗 F2 的额度；缓存命中的调用不计入调用上限。
- **F5 运行内去重**：同一次运行中，相同的工具和参数重复请求时直接返回已有结果，不重复执行，也不重复计数（replan、调整、修复复用同一批数据）。
- **F6 研究结论携带天气**：预报由工具结果确定性写入研究结论，不允许模型自行转述或编造；草案阶段能看到逐日天气。预报缺失时，研究结论中天气为空且不阻塞。
- **F7 雨天校验**：预报显示某天有雨或雪，且该天户外点位占比超过 60% 时，产生阻塞级违规并触发一次修复；没有预报时保持现有 warning 行为不变。
- **F8 开关与状态**：天气工具仅在数据源密钥配置时启用，其状态和禁用原因出现在 `/api/meta`；禁用时研究提示词中不出现该工具，规划流程与当前一致。
- **F9 可观测性**：每次天气工具调用产生事件，事件需区分真实查询与缓存命中；研究降级原因能区分「未配置」「超时」「上游失败」。

## 非功能需求

- **N1 软失败与时延**：天气查询失败、超时或数据为空都不得使运行失败；天气调用受研究阶段既有总时限约束，不额外延长整体等待时间。
- **N2 缓存复用**：使用现有插件缓存存储，不引入 Redis 或新基础设施；缓存读写失败按未命中处理，不影响主流程；过期清理沿用现有机制。
- **N3 无数据库变更**：研究结论中的天气字段存放在既有 JSON 列中，不新增表或迁移；日期使用本地时区，温度为摄氏度，并保留数据来源标注。
- **N4 兼容性**：未配置密钥或工具关闭时，行为与当前版本完全一致；现有工具注册名、事件名和 `/api/meta` 既有字段不变。
- **N5 并发一致性**：同一缓存键的并发未命中最多只发起一次上游请求（当前为单实例部署）；额度计数在缓存判断之后进行，且并发安全。
- **N6 可配置性**：缓存有效期、单工具超时、单工具次数上限通过环境变量配置，并有合理默认值；非法值在启动时拒绝，沿用现有配置校验方式。
- **N7 可测试性**：缓存键标准化、缓存命中不占额度、运行内去重、雨天校验均可在不访问外网的情况下用单元测试覆盖。

## 不做的事

- 不做「按天气挑选出行起始日期」：预报窗口有限，起始日期仍由用户指定或沿用默认值。
- 不做历史气候、雨季统计或超出预报窗口的推断。
- 不新增天气供应商：继续使用高德，不接和风、心知、彩云或 Open-Meteo。
- 不做 POI 详情、周边餐饮、攻略正文抓取——留给后续迭代。
- 不做实时路况或按小时级天气排程。
- 不做天气预报的前端展示，本期只影响研究结论、草案与校验。
- 不保证每次规划都查询天气：天气是模型按需调用的工具，用户没有相关诉求时可以不调用。
- 不调整酒店与攻略工具的 TTL 和单工具次数上限；只统一「缓存命中不占额度」这一语义，该语义对全部工具生效。
- 不引入分布式锁或跨实例协调：运行内去重与缓存足以覆盖当前单实例部署。

## 验收标准

- **AC1（F1）**：给定合法城市和窗口内日期，查询返回逐日日期、天气、温度并标注来源；城市非法或超出窗口时返回结构化错误，研究流程继续并正常出计划。
- **AC2（F2）**：单次运行内天气工具最多发起 1 次上游查询；第 2 次请求收到可读的额度错误，运行不中断。
- **AC3（F3/F9）**：有效期内重复相同城市和日期范围的查询，第二次不发起上游请求、结果一致，且调用事件标记为缓存命中；同一时段查询不同城市，结果互不串用。
- **AC4（F4）**：缓存命中后，本次运行剩余可用调用额度不变；真实上游调用使额度减少 1。
- **AC5（F5）**：同一运行内相同工具和参数请求两次，第二次不执行、不计数；缓存过期后再次请求会重新查询。
- **AC6（F6）**：工具成功时，研究结论中的逐日预报与工具返回逐字一致，草案阶段可见；工具失败时结论中无天气字段，运行照常完成。
- **AC7（F7）**：预报有雨且当天户外占比超过 60% 时产生阻塞级违规并进入修复；无预报时只产生与当前一致的 warning。
- **AC8（F8）**：密钥存在时 `/api/meta` 报告天气工具启用且无误导性原因；密钥缺失时报告禁用并给出原因，研究工具列表中不含该工具。
- **AC9（N1/N5/F9）**：上游超时或报错时运行以无天气状态完成，降级原因能区分未配置、超时与上游失败；并发的相同缓存键未命中最多产生 1 次上游请求。
- **AC10（N7）**：缓存键标准化、额度语义、运行内去重、雨天规则均有不依赖外网的单元测试；现有测试全部通过，编译无错误。
- **端到端**：用户规划两天北京行程且第一天预报有雨 → agent 查询天气 → 草案或修复把户外密集内容移出雨天 → 产出计划；5 分钟内的第二次运行显示缓存命中且不消耗额度。
