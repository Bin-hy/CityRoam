# TripPilot v1.4 天气工具 Checklist

状态：待审批（checklist）
日期：2026-11-20
对应 spec：`docs/mew-spec/v1.4-weather-tool/spec.md`

> 每一项通过运行代码或观察行为验证，聚焦系统行为，不依赖具体文件位置。

## 实现完整性

- [ ] 天气工具在研究工具列表可见（验证：配置密钥后，研究提示词的已启用工具包含 `get_weather`）。
- [ ] 工具返回逐日日期、白天/夜间天气、最高/最低温并标注来源（验证：示例输入调用，检查 JSON）。
- [ ] 城市非法或日期超出预报窗口时返回结构化错误，研究流程继续（验证：假数据源单测 + 研究不中断）。
- [ ] 缓存键包含标准化城市与日期范围，不同城市结果不串用（验证：单测比较键与结果）。
- [ ] 缓存有效期生效（验证：假时钟前进 TTL 后再次查询会重新请求）。
- [ ] 缓存命中不消耗调用额度（验证：`maxCalls=1` 时第二次同键请求仍成功）。
- [ ] 同一次运行内重复的相同工具请求只执行一次、不计数（验证：假工具计数为 1，结论 `tool_calls` 不增加）。
- [ ] 同一缓存键的并发未命中最多触发一次上游请求（验证：并发单测中假数据源调用计数为 1）。
- [ ] 研究结论中的天气来自工具结果，模型伪造的天气被覆盖（验证：模型输出带假天气，结论仍为工具值）。
- [ ] 雨天且户外占比超过 60% 时产生 C13 阻塞级违规（验证：领域单测 + 校验输出阻塞计数）。
- [ ] 没有预报时只保留现有 C11 warning，不产生 C13（验证：无预报输入的校验结果）。
- [ ] `/api/meta` 暴露天气启用状态与禁用原因（验证：HTTP 响应断言）。
- [ ] 上游失败或超时时运行以无天气状态完成，并产生警告（验证：假数据源返回错误，研究完成事件与结论）。
- [ ] 调用事件能区分真实查询、缓存命中与合并命中（验证：捕获事件流断言标志）。

## 集成

- [ ] 插件状态列表包含天气，且顺序稳定、不影响酒店与攻略状态（验证：装配测试）。
- [ ] 天气工具的单次运行上游上限为 1（验证：连续两次真实查询，第二次收到额度错误）。
- [ ] 校验节点收到研究结论并合并 C13，现有 C1–C12 结果不变（验证：校验测试对比既有用例）。
- [ ] 草案阶段能读到逐日天气（验证：渲染草案提示词，包含 `weather` 数据）。
- [ ] 未配置密钥时天气工具不注入研究提示词，规划行为与当前一致（验证：装配测试 + 提示词断言）。
- [ ] `/api/meta` 既有 `hotels`、`guides` 字段不变（验证：元数据测试）。

## 编译与测试

- [ ] 项目编译无错误（验证：`go build ./...`）。
- [ ] 静态检查通过（验证：`go vet ./...`）。
- [ ] 全量单元测试通过（验证：`go test ./...`）。
- [ ] 并发敏感包通过竞态检测（验证：`go test -race ./internal/plugins ./internal/agent`）。

## 端到端场景

- [ ] 场景 1：两天北京行程、第一天预报有雨、候选含室内与户外地点 → agent 查询天气 → 方案中雨天户外占比不超过 60%，或不满足时进入修复；完成事件天气状态为 `ok`。
- [ ] 场景 2：30 分钟内的第二次相同查询 → 事件标记缓存命中、额度不减少，方案照常生成。
- [ ] 场景 3：`AMAP_WEB_KEY` 为空 → `/api/meta` 报告天气禁用及原因；研究提示词不含该工具；计划正常生成。
- [ ] 场景 4：天气上游超时或 500 → 运行完成，完成事件天气状态为 `timeout` 或 `unavailable`，结论警告包含「天气不可用」，计划无天气但不失败。
- [ ] 场景 5：同一次研究中模型重复调用天气工具 → 只执行一次，结论中的工具调用数只计 1。
- [ ] 场景 6：雨天户外密集但候选集没有可替代室内点 → 修复轮次受既有上限约束后仍出方案，不出现无限修复。
