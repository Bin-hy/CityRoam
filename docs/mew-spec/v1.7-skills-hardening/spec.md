# TripPilot v1.7 技能渐进加载与治理 Spec

状态：已批准（spec）
日期：2026-11-20
关联：[技能运维文档](../../skills.md) · [v1.6 结果页](../../mew-spec/v1.6-result-views/spec.md)

## 背景

v1.7 之前，技能已经做到提示词层渐进披露：研究提示词只列出技能名称、版本和用途，模型调用 `load_skill` 后才把正文放进工具消息。版本由 `skills.lock.json` 和 SHA-256 固定，启动时校验。

但当前实现仍在三个层面不符合渐进披露和企业治理要求：

- `admit` 节点把注册表中所有技能的完整正文写入 `runs.state`，即使本次运行没有启用研究工具、技能根本不会被加载；每个图阶段结束又会重写整个 state，形成不必要的写放大。
- 技能目录没有总预算。描述上限 1024 字符、技能上限 32 个，最坏情况下目录本身可达数万字符，可能挤占候选点、约束和研究提示的上下文。
- 已发出 `research.skill_loaded` 事件，但 Web 对话流和评测轨迹没有消费；也没有可重复的“该不该加载某个技能”的触发评测。

Web 端不实现技能加载，只消费后端 SSE 事件；本次改动的主体是 Go 后端与 Web 轨迹展示。

需要说明当前的数据来源：技能清单和正文目前来自本地 `skills/` 目录，不是数据库；技能加载没有逐请求的数据库读取。真正与数据库相关的是运行状态的反复写入。缓存层仍按“技能未来可以落到数据库”设计：先查清单和版本，命中的请求不产生源读取；未命中或版本不符时才回源加载正文并回填。Redis 作为分布式 L3 预留，本期不引入依赖。

## 目标

- 端到端渐进披露：提示词只常驻目录，正文按需解析；新运行的 `runs.state` 只保留技能 pin，不保留未加载技能的正文。
- 固定版本可复现：运行中加载的正文必须与开始时固定的版本和哈希一致，绝不静默替换为当前启用版本。
- 目录可预算：目录文本有明确上限，超限在启动阶段失败，而不是悄悄挤压研究上下文。
- 加载可观测：正常运行和评测轨迹都能看到加载了哪个技能、哪个版本；不展示正文。
- 可评测：提供可选的触发评测命令，用真实模型验证“相关时加载、不相关时不加载”。
- 三级缓存：L1 缓存技能清单与版本索引，L2 缓存完整正文，L3 预留 Redis；先校验清单/版本，未命中或版本不符时回源加载并回填，避免重复源读取。
- 不新增数据库迁移，不改变研究工具边界和硬约束语义。

## 功能需求

### 运行状态与解析

- **F1 运行级技能 pin**：新运行在开始时固定当时的技能目录（名称、版本、用途描述、SHA-256），并写入运行状态；状态中不包含未加载技能的正文。无论技能正文总量多大，技能相关的状态体积只随目录增长。
- **F2 按需解析固定版本**：`load_skill` 被调用时，按 pin 解析正文，并校验名称、版本和 SHA-256。解析结果可以在本次研究内缓存；单次运行最多加载 3 个不同技能的上限保持不变。
- **F3 禁止版本回退**：当固定版本缺失、文件被修改或哈希不匹配时，不得改用当前启用版本，也不得用同名技能的其他版本顶替。
- **F4 固定版本缺失的行为**：`load_skill` 返回稳定的错误码；研究状态标记为 degraded，原因可识别为“固定技能不可用”；运行继续完成方案生成，但事件和界面必须明确告知缺少哪个技能版本。
- **F5 旧状态兼容**：已经包含完整技能正文的旧运行状态继续使用其中的正文，不需要数据迁移；新运行不再写入这些正文字段。

### 目录预算与编写规范

- **F6 目录硬预算**：名称、版本、描述和正文沿用现有硬校验，并新增：描述必须单行且不超过 300 字符；渲染后的技能目录文本不超过 8 KiB；技能总数不超过 32 个。启动、`skills -write`、`skills -verify` 和 lint 使用同一套校验；超限时启动失败，错误信息指出具体技能和限制。
- **F7 编写规范 lint**：`cmd/skills` 增加 lint 模式，对正文超过 500 行、描述缺少明显适用场景提示（如“当/用于/需要/适合/when/use when/for”）给出 warning；`-strict` 时把 warning 当作错误，供 CI 使用。
- **F8 版本保留规则**：文档明确：只要可能存在未完成或可恢复的运行，固定版本目录不得删除；删除后已 pin 但尚未加载的技能将不可用。该规则由运维遵守，不在本次增加自动 GC。

### 触发评测

- **F9 触发评测命令**：新增可选的技能触发评测命令，使用真实模型、固定的评测技能集和一个无副作用的 research 工具，运行“应加载/不应加载”的用例，校验实际加载的技能集合。命令输出每个用例的期望、实际和耗时，存在失败时以非零状态退出。
- **F10 评测隔离**：评测使用独立的 fixture 技能目录，不进入生产技能目录、不影响生产目录预算；至少包含一个正例和一个负例，能够验证相似技能的区分度。评测默认不进入 `go test` 或常规 CI，需要显式配置模型凭据后运行。

### 技能缓存

- **F14 L1 清单缓存**：进程内缓存当前启用技能清单（名称、版本、描述、哈希）和每个技能的可用版本索引。读取目录或解析 pin 时先查清单，命中时不重复读取或解析本地技能文件，也不查询数据库。
- **F15 L2 正文缓存**：按“名称 + 版本 + 哈希”缓存完整正文。命中直接返回；未命中、版本不符或哈希不符时，从源加载正文、校验后回填。缓存按条目数和字节数设上限，满时淘汰；旧版本正文与当前启用版本使用同一套缓存规则。
- **F16 L3 分布式缓存预留**：缓存抽象保留 L3 位置，用于未来的 Redis/多实例共享缓存；本期只实现 L1/L2，不引入 Redis 客户端或连接配置，只在接口、文档和代码标记中预留。
- **F17 先校验再回源**：使用缓存清单时，以不超过 30 秒的间隔对照本地锁文件和技能目录指纹；间隔内直接使用缓存，指纹不一致时使 L1/L2 相关条目失效并重新加载。正文回源后必须校验 pin 中的名称、版本和哈希；禁止用当前启用版本或同名其他版本顶替 pin。重载失败时保留上一次有效清单供已固定运行继续使用，新运行返回明确的技能不可用错误，不使用部分加载结果。
- **F18 并发与观测**：同一缓存键的并发未命中合并为一次源加载，避免大量用户同时穿透；记录命中、未命中、回源、淘汰计数。缓存不得改变运行级 pin 语义。
- **F19 源无关**：当前源是本地文件，未来可替换为数据库；调用方只依赖“按 pin 获取正文”的接口。缓存命中或 L1 命中时不产生源读取，从而在数据库化后避免逐请求读库。

### 可观测与文档

- **F11 加载事件**：`research.skill_loaded` 事件包含技能名称、版本和 SHA-256；`research.completed` 保留本次实际加载的技能列表。研究降级时，原因中包含缺失技能的名称和版本。
- **F12 Web 轨迹**：对话流在技能加载时显示非阻断的加载项（名称和版本），评测轨迹显示对应事件；界面只显示元数据，不显示技能正文或完整描述。
- **F13 运维文档**：更新技能文档和 README，说明 pin-only 状态、按需解析与缺失行为、目录预算、编写规范、lint/评测命令和版本保留规则；Makefile 增加 lint 与评测入口。

## 非功能需求

- **N1 状态体积**：新运行的技能相关状态体积上限由目录预算决定，不再随技能正文总量增长；每个图阶段不再重写全部技能正文。
- **N2 调用成本**：不增加规划阶段的模型调用；技能仍按需加载，单次运行最多 3 个。
- **N3 兼容性**：不新增数据库迁移；旧运行状态可以恢复并继续使用原有正文。
- **N4 失败策略**：启动阶段 fail-fast；运行阶段禁止版本回退，缺失固定版本时显式降级。
- **N5 评测可选**：触发评测不进入默认测试和 CI；缺少模型凭据时给出清晰提示，不静默跳过。
- **N6 安全边界**：解析路径必须使用已校验的名称和版本；哈希不匹配即拒绝；技能正文不进入 `/api/meta`、公开分享页或日志。
- **N7 性能**：按需解析只读取单个不超过 32 KiB 的文件，并在本次研究内缓存；不显著占用 12 秒研究预算。
- **N8 缓存边界**：L1 条目受目录预算约束；L2 条目数和总字节数有硬上限；缓存不得无界增长，淘汰后仍能按 pin 从源恢复。
- **N9 缓存与 pin**：缓存键包含哈希；清单刷新、版本升级或缓存淘汰都不能改变已固定 run 的版本，也不能让缓存命中绕过哈希校验。
- **N10 并发保护**：同一缓存键的并发回源必须合并，避免缓存击穿；回源失败不得写入错误内容。
- **N11 Redis 预留**：本期不新增 Redis 依赖、连接串或部署组件；L3 只保留扩展点和文档标记，避免出现“配置了但不生效”的隐性行为。

## 不做的事

- 不做技能包内的 `references/`、`scripts/`、`assets/` 等资源层加载。
- 不引入内容寻址存储、对象存储或新的数据库表；旧版本继续由部署目录保留。
- 不实现 Redis L3、跨实例缓存失效或分布式锁；本期只在接口和文档预留。
- 不做签名、按租户/环境启用、后台技能管理和在线编辑。
- 不做语义检索、top-k 技能召回；目录仍由模型自行判断。
- 不做自动版本晋级、自动回滚或无审阅的热更新；F17 的指纹刷新只用于发现本地清单变化并重新校验，不改变锁文件中的版本选择。
- 不改变研究提示词的信任边界、工具权限、候选集规则和硬约束校验。
- 不在公开分享页展示技能正文、描述或加载轨迹。

## 验收标准

- **AC1（F1）**：新运行的运行状态包含技能 pin，不包含未加载技能的正文；准备 10 个 10 KiB 正文的技能时，技能相关状态体积仍只接近目录大小。
- **AC2（F2/F3）**：运行固定技能 v1 后把启用版本升级到 v2，再恢复该运行；`load_skill` 返回 v1 的正文和哈希，不返回 v2。
- **AC3（F5）**：使用包含完整技能正文的旧运行状态恢复，`load_skill` 继续使用旧正文，不需要迁移。
- **AC4（F6）**：描述超过 300 字符或含换行、目录超过 8 KiB、正文超过 32 KiB 时启动失败，错误指出具体技能和限制。
- **AC5（F7）**：`make skills-lint` 对超长正文和缺少适用场景提示给出 warning；加严格模式后以非零状态退出。
- **AC6（F9/F10）**：`make skills-eval` 的正例和负例都通过；故意改错期望后命令以非零状态退出；未配置模型凭据时提示如何配置。
- **AC7（F11/F12）**：完成一次触发技能加载的真实研究后，对话流出现“技能名称@版本”的加载项，评测轨迹出现对应事件；页面和事件中不包含技能正文或完整描述。
- **AC8（F4）**：删除已 pin 的旧版本目录后恢复运行，模型请求该技能时研究标记为 degraded，原因指向固定技能不可用，且没有加载当前版本，运行仍产出方案。
- **AC9（F13/N3）**：`go build ./...`、`go test ./...`、`go vet ./...`、`make skills-verify` 全部通过；仓库没有新增数据库迁移。
- **AC10（F11/N6）**：`research.skill_loaded` 和 `research.completed` 的载荷包含名称、版本和哈希；公开分享接口不包含技能正文或描述。
- **AC11（F14/F17）**：清单命中时不重复读取或解析技能文件；修改本地锁文件或技能目录指纹后，下一次访问使清单和正文缓存失效并重新校验。
- **AC12（F15/F19）**：同一版本正文第一次加载后，后续运行命中 L2，不再读取源；不同版本或不同哈希使用不同缓存条目，互不覆盖。
- **AC13（F18/N10）**：多个并发请求同时加载同一个未缓存技能时，只产生一次源加载，所有请求得到相同正文；加载失败不会写入缓存。
- **AC14（F15/N8）**：超过 L2 条目或字节上限时按策略淘汰；淘汰后再次请求可按 pin 从源恢复，缓存不会无界增长。
- **AC15（F16/N11）**：默认启动不要求 Redis，也不读取 Redis 配置；代码和文档中存在明确的 L3 预留标记，未配置 Redis 时无隐性行为变化。
- **AC16（F17）**：本地技能被改坏导致清单重载失败时，已固定的运行仍可按 pin 使用已有正文；新运行以明确的技能不可用错误结束，不会使用部分加载或旧清单静默继续。
