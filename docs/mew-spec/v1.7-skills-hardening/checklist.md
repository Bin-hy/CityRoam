# TripPilot v1.7 技能渐进加载与治理 Checklist

状态：已批准（checklist）
日期：2026-11-20
依据：[spec.md](spec.md)、[plan.md](plan.md)、[task.md](task.md)（均已批准）

> 每一项通过运行命令、观察接口或操作界面来验证；验收时记录实际输出，不以“应该通过”作为证据。

## 一、运行状态与版本固定

- [ ] **C1（AC1/F1）新运行只固定目录**
  验证：新建一个运行并读取其持久化状态，存在技能名称/版本/描述/哈希，不存在未加载技能的正文；准备 10 个 10 KiB 正文的技能时，技能相关状态体积 < 64 KiB。
- [ ] **C2（AC2/F2/F3）升级不改进行中运行**
  验证：运行固定技能 v1 后，将启用版本升级到 v2，再恢复该运行；`load_skill` 返回 v1 的正文和 SHA-256，事件中为 v1，未出现 v2。
- [ ] **C3（AC3/F5）旧状态正文可用**
  验证：用包含完整技能正文的旧运行状态恢复，`load_skill` 继续返回旧正文；无需数据迁移，状态字段未被改写。
- [ ] **C4（AC8/F4）缺失固定版本显式降级**
  验证：删除已 pin 的旧版本目录后恢复运行，模型请求该技能；研究状态为 degraded，原因包含 `name@version`，未加载当前启用版本，运行仍产出方案并可完成。
- [ ] **C5（F1）恢复运行不重新读目录**
  验证：恢复一个 `skills_pinned=true` 的运行，观察没有新的清单扫描/源读取；固定时的目录保持不变。

## 二、目录预算与编写规范

- [ ] **C6（AC4/F6）预算超限启动失败**
  验证：分别构造描述超过 300 字符、描述含换行、正文超过 32 KiB、渲染目录超过 8 KiB 的技能目录，启动/校验命令失败，错误指出具体技能与限制。
- [ ] **C7（AC5/F7）lint 警告与严格模式**
  验证：`make skills-lint` 对正文超过 500 行、描述缺少触发词的技能输出 warning 且退出 0；`make skills-lint-strict` 对同类问题非零退出；当前生产技能在严格模式下通过。
- [ ] **C8（F8）版本保留规则**
  验证：`docs/skills.md` 明确“存在可恢复运行时不得删除固定版本”；升级到 1.0.1 后 1.0.0 目录仍存在。
- [ ] **C9（F6）提示词目录与校验一致**
  验证：研究提示词中的技能目录行与预算校验使用同一格式；目录接近 8 KiB 时仍可启动，超过时启动失败。

## 三、事件、API 与 Web

- [ ] **C10（AC7/F11/F12）加载可见且不泄露正文**
  验证：完成一次触发技能加载的真实研究后，Web 对话流出现“技能名称@版本”加载项，评测轨迹出现对应事件；页面与事件载荷不包含技能正文或完整描述。
- [ ] **C11（AC10/N6）事件与分享安全**
  验证：`research.skill_loaded` 和 `research.completed` 载荷包含名称、版本、SHA-256；公开分享接口不包含技能正文、描述、pin 或加载轨迹。
- [ ] **C12（F11）降级原因可定位**
  验证：固定技能不可用时，`research.degraded` 的原因包含缺失技能的名称和版本，界面显示可读的降级信息。
- [ ] **C13（F13）meta 反映最近有效目录**
  验证：启动后 `/api/meta` 返回技能 name/version/sha256；清单刷新成功后再次请求可见新版本；刷新失败时仍返回上次有效目录，不暴露内部错误。

## 四、缓存与并发

- [ ] **C14（AC11/F14/F17）L1 命中零源读取**
  验证：30 秒内连续运行/请求只使用缓存目录，不重复读取或解析技能文件；修改锁文件或技能指纹后，下一次访问触发重新校验并更新目录。
- [ ] **C15（AC12/F15/F19）L2 按 pin 命中**
  验证：同一版本正文第一次加载后，后续运行命中 L2，源读取次数不增加；不同版本或不同哈希使用不同条目，互不覆盖。
- [ ] **C16（AC13/N10）并发未命中合并**
  验证：多个并发请求同时加载同一个未缓存技能，只发生一次源加载，所有请求得到相同正文；加载失败不写入缓存。
- [ ] **C17（AC14/N8）缓存有界且可恢复**
  验证：超过条目或字节上限时发生淘汰；被淘汰的技能再次请求可按 pin 从源恢复；长时间运行缓存条目和字节数不无限增长。
- [ ] **C18（AC16/F17）刷新失败不影响已固定运行**
  验证：本地技能被改坏导致清单重载失败；已固定且正文已缓存的运行仍可 `load_skill`，新运行以明确的 `skills_unavailable` 失败，不使用部分加载或旧清单静默继续。
- [ ] **C19（AC15/F16）无 Redis 隐性行为**
  验证：默认启动不要求 Redis，不读取 Redis 配置；`go.mod` 无 Redis 依赖；代码中有明确的 L3 预留标记但无实例化路径。

## 五、触发评测

- [ ] **C20（AC6/F9/F10）评测正负例可判定**
  验证：配置模型凭据后 `make skills-eval` 的正例、区分例、负例全部通过；故意改错一个期望后命令非零退出；未配置凭据时打印所需环境变量并非零退出。
- [ ] **C21（F10）评测与生产隔离**

## 七、端到端场景

- [ ] **E1 正常渐进加载**
  用户发起需要攻略/住宿的行程 → 研究提示只带目录 → 模型调用 `load_skill` → Web 出现技能加载项 → 研究完成，方案生成。观察点：正文只在工具消息中，状态无正文，界面无描述/正文。
- [ ] **E2 升级期间恢复运行**
  运行 A 固定 v1 后等待用户输入 → 部署启用 v2 → 恢复 A 并触发技能加载 → 得到 v1 正文；新建运行 B 得到 v2。观察点：A 的事件、正文哈希与 v1 一致。
- [ ] **E3 固定版本被删除**
  运行 A 固定 v1 且正文已缓存 → 删除 v1 目录 → 恢复 A 并请求技能 → 若命中 L2 则继续；若未缓存则研究 degraded，原因含 v1，方案仍生成。新建运行因清单扫描失败明确报错。
- [ ] **E4 缓存命中与淘汰**
  连续多次运行同一技能 → 首次回源后后续命中 L2，源读取计数不增长；用大量不同版本/哈希制造压力 → 触发淘汰，再次请求可恢复，进程内存不持续增长。
- [ ] **E5 触发评测**
  配置模型凭据 → `make skills-eval` 输出三个用例的期望、实际和耗时 → 全部通过；改错期望后非零退出。
