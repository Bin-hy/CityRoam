# TripPilot v1 MVP Checklist

> 状态：已批准（2026-11-19）
> 验证原则：每一项都通过运行代码、观察行为或对比输出来验证；先有证据再下结论。代码重构但行为不变时，本清单仍然适用。

## 1. 需求与约束

- [ ] **R-01** 一句话输入能生成结构化约束和一份行程。（验证：`POST /api/trips` 输入「北京两天，预算800，喜欢历史和咖啡，不要太赶，周一出发」，SSE 出现 `constraint.parsed`，约束包含城市、天数、预算、兴趣、节奏；工作台展示行程；AC1）
- [ ] **R-02** 缺少城市或天数时追问，不擅自补默认值。（验证：输入「想去北京玩」，run 停在 `awaiting_user`，SSE 出现 `constraint.needs_input`，页面询问城市/天数；补充后能继续；AC2）
- [ ] **R-03** 硬约束和软偏好可分别编辑、互相切换，旧版本保留。（验证：工作台把预算从软改为硬并重新生成；旧版本仍在列表，新版本约束中 `hard` 包含 `budget`；AC3）
- [ ] **R-04** 候选集为 40～60 个 POI，必去点在集合内。（验证：查看 `candidate.retrieved` 事件，候选数在 40–60；必去点 ID 出现在候选列表；AC4）
- [ ] **R-05** 模型输出未知 POI ID 时被拒绝。（验证：用 fake LLM 返回一个不在候选集的 ID，运行重试一次后失败或重新生成；最终版本不含该 ID；AC4）
- [ ] **R-06** 行程草案包含每天起止时间、时间块、交通方式、费用；餐饮开启时每天至少一个餐饮块。（验证：打开最终行程，每天有 `start/end`、`transit` 块、`cost`；餐饮开启时每天至少一个 `meal`；AC5）
- [ ] **R-07** 所有版本中的 POI 都来自候选集，不出现外部地点。（验证：遍历版本 JSON，所有 `poi_id` 均属于该 run 的候选集；无候选集外 ID；AC4、AC5）

## 2. 校验与修复

- [ ] **V-01** C1～C12 每条规则都能独立触发。（验证：运行 `go test ./internal/domain/validator/...`，每条规则至少一个通过用例和一个阻断用例；AC6）
- [ ] **V-02** 每条违规包含类型、级别、涉及时间块和修复建议。（验证：构造违规，检查 JSON 含 `code`、`level`、`day`、`block_id`、`message`、`suggestion`；AC6）
- [ ] **V-03** 修复最多 3 轮。（验证：用冲突用例运行，SSE 最多出现 3 次 `repair.completed`；第 4 次不出现；AC7）
- [ ] **V-04** 停止条件生效：阻断清零、3 轮、连续两轮无改善、用户取消。（验证：分别构造四类场景，run 在对应条件停止，不悬挂；AC7）
- [ ] **V-05** 停止后输出当前最优解、剩余违规、停止原因和放宽建议。（验证：构造 3 轮仍有阻断的用例，最终响应包含最优行程、剩余违规、stop reason、建议；AC7）
- [ ] **V-06** 修复循环不会无限运行。（验证：运行 20 条用例，无 run 超过 3 轮或超过 60 秒仍未结束；AC7）

## 3. 调整与版本

- [ ] **A-01** 调整先出提案，用户接受前不生成新版本。（验证：提交「第二天下午轻松点」，run 停在 `awaiting_user`，返回 proposal；版本列表没有新增；AC8）
- [ ] **A-02** 接受后生成新版本，拒绝后保留原版本。（验证：同一提案分别 accept 和 reject；accept 后版本数 +1，reject 后版本数不变；AC8）
- [ ] **A-03** 只改受影响范围，未受影响的天不变。（验证：调整第 2 天，查看 diff，第 1、3 天逐字段一致；AC8）
- [ ] **A-04** 无法理解调整对象时追问，不猜测。（验证：输入「改一下」，系统要求补充调整对象，不生成提案；AC8）
- [ ] **A-05** 支持版本列表、任意两版差异、回退。（验证：打开两版 diff；回退后当前版本指针变化，原版本仍保留；版本包含行程、约束、违规、原因；AC9）

## 4. 展示与分享

- [ ] **U-01** 地图按天展示路线，颜色区分。（验证：浏览器打开工作台，地图上每天一条不同颜色路线；AC10）
- [ ] **U-02** 时间轴与地图联动。（验证：点击时间轴块，地图居中并高亮对应 marker；点击 marker 反向高亮时间块；AC10）
- [ ] **U-03** 地图加载失败时时间轴和文本仍可用。（验证：移除 `VITE_AMAP_JS_KEY` 后刷新，地图区显示降级提示，时间轴、预算、版本仍可用；AC10）
- [ ] **U-04** 分享链接无需登录、只读、带 AI 标识和来源。（验证：打开 `/share/{slug}`，无编辑按钮，显示行程、预算、AI 标识、数据来源；AC11）
- [ ] **U-05** 能复制纯文本行程。（验证：点击复制，剪贴板内容包含每天时间、地点、交通、费用；AC11）
- [ ] **U-06** 未主动分享的行程不可公开访问；分享页只展示最终版本。（验证：未创建分享的 trip 请求分享接口返回 404；分享页不显示 draft 版本；AC11）

## 5. 运行追踪与评测

- [ ] **T-01** SSE 推送完整事件序列。（验证：一次运行中能看到 `run.started`、`stage.*`、`tool.*`、`validation.result`、`repair.*`、`plan.updated`、`run.awaiting_user` 或 `run.completed`；AC12）
- [ ] **T-02** SSE 断线后能续传。（验证：中途关闭连接，带 `Last-Event-ID` 重连；缺失事件被补发，无重复或丢失；AC12）
- [ ] **T-03** 事件落库，可回放。（验证：通过 trace 接口或数据库查看完整 `run_events`，顺序与 SSE 一致；AC12）
- [ ] **T-04** 20 条评测用例存在且分布正确。（验证：`jq -s 'length' eval/cases/*.json` 为 20；覆盖 1～4 天、预算、节奏、必去、雨天、闭馆；AC13）
- [ ] **T-05** 一键评测输出指标表。（验证：运行评测，报告包含硬约束满足率、平均修复轮数、延迟、POI 有效率、JSON 合法率、人工评分；AC13）
- [ ] **T-06** 失败用例可回放到具体步骤。（验证：打开失败用例，能看到对应 run 的 trace 和违规；AC13）
- [ ] **T-07** LLM JSON 合法率 ≥99%。（验证：20 条用例运行后统计 JSON 解析成功次数 / 总调用次数，含一次重试；AC13）

## 6. 非功能

- [ ] **N-01** 性能达标。（验证：需求解析 ≤5 秒；3 天行程 p95 ≤60 秒；SSE 心跳间隔 ≤2 秒；AC14）
- [ ] **N-02** 工具与模型超时受控。（验证：模拟高德超时，工具重试 2 次后降级；LLM 超时 60 秒；修复不超过 3 轮；AC15）
- [ ] **N-03** 服务重启后能恢复等待状态。（验证：run 在 `awaiting_user` 时重启 API，再次 resume 能继续，事件不丢；AC15）
- [ ] **N-04** 单次规划模型成本 ≤0.5 元。（验证：按 token 用量和模型单价计算，或查看 provider 账单；AC17）
- [ ] **N-05** 密钥只在服务端；输入有限制；IP 限流生效。（验证：浏览器网络面板看不到 `AMAP_WEB_KEY`、`LLM_API_KEY`；超长输入被拒绝；同一 IP 第 11 次请求返回 429；AC16）
- [ ] **N-06** 合规标识齐全。（验证：分享页有 AI 生成标识、数据来源、价格估算说明；数据库无用户身份字段；AC16）
- [ ] **N-07** 移动端可读。（验证：375px 视口无横向滚动，地图和时间轴可切换；AC10）
- [ ] **N-08** 仓库无真实密钥。（验证：`git grep -i 'api_key\\|secret'` 只命中变量名和 `.env.example`；`.env` 不在版本控制；AC16）

## 7. 集成

- [ ] **I-01** API → Runner → Graph → Store → SSE 链路打通。（验证：创建行程后，数据库有 trip/run/version/events，SSE 同时收到事件；AC1、AC12）
- [ ] **I-02** 前端收到 `plan.updated` 后自动刷新，不需要手动刷新页面。（验证：浏览器停留工作台，修复完成后行程和版本自动更新；AC10）
- [ ] **I-03** 高德失败时 native 工具降级。（验证：断开高德网络或使用错误 Key，行程仍能生成，路线标 `estimated`；AC15）
- [ ] **I-04** MCP 适配链路可用，且不污染候选集。（验证：调用 mock MCP 工具，`tool_calls` 有记录，结果进入 `evidence`，无坐标时不进入候选；AC4）
- [ ] **I-05** 分享只指向最终版本。（验证：分享页显示的版本与 trip 的 accepted 版本一致；AC11）
- [ ] **I-06** 评测接口受 Admin token 保护。（验证：无 token 访问 `/api/eval/*` 返回 401；AC16）
- [ ] **I-07** 创建和调整具备幂等性。（验证：同一 `Idempotency-Key` 重复 POST，返回同一 trip/run，不重复执行；AC16）
- [ ] **I-08** 并发受控。（验证：同时发起 5 个 run，最多 3 个 `running`，其余 `queued`，完成后依次执行；AC15）

## 8. 编译、测试与部署

- [ ] **B-01** Go 编译和测试通过。（验证：`go build ./...`、`go vet ./...`、`go test -race ./...` 全部成功）
- [ ] **B-02** 前端测试和构建通过。（验证：`cd web && npm ci && npm test && npm run build` 成功）
- [ ] **B-03** 端到端测试通过。（验证：`npx playwright test` 成功）
- [ ] **B-04** OpenAPI 契约合法。（验证：`npx @redocly/cli lint openapi.yaml` 通过）
- [ ] **B-05** 数据库迁移和 sqlc 可用。（验证：`sqlc generate` 成功；`goose up` 成功；`goose down` 可回滚）
- [ ] **B-06** Compose 可启动。（验证：`docker compose -f deploy/docker-compose.yml config` 无错误；`docker compose up -d` 后 caddy/api/postgres 健康）
- [ ] **B-07** 健康检查可用。（验证：`curl /healthz` 和 `/readyz` 返回 200）
- [ ] **B-08** lint 通过。（验证：`golangci-lint run` 和前端 lint 无错误）
- [ ] **B-09** CI 全绿。（验证：GitHub Actions 的 backend、frontend、docker config job 全部通过）

## 9. 端到端场景

- [ ] **E-01 黄金路径**：输入北京两天 → 看到逐轮 trace → 最终行程 → 接受 → 调整第二天 → 接受 → 生成分享链接；全程无需手动刷新页面，分享页只读可打开。（AC1、AC7、AC8、AC10、AC11、AC12）
- [ ] **E-02 缺失信息**：输入「想去北京玩」→ 系统追问城市/天数 → 补充 → 继续生成 → 得到行程。（AC2）
- [ ] **E-03 违规修复**：使用闭馆日或路程冲突用例 → 看到 `validation.result` 阻断 → 看到修复轮 → 最终阻断清零，或明确显示剩余违规和放宽建议。（AC6、AC7）
- [ ] **E-04 调整拒绝**：提交调整 → 看到提案 → 拒绝 → 版本数不变，原行程保留。（AC8、AC9）
- [ ] **E-05 降级**：移除地图 Key + 模拟高德超时 → 地图显示降级提示，时间轴和预算仍可用，路线标估算。（AC10、AC15）
- [ ] **E-06 重启恢复**：run 停在 `awaiting_user` → 重启 API → resume → 继续执行，事件不丢。（AC15）
- [ ] **E-07 安全与隐私**：同一 IP 第 11 次请求返回 429；未分享 trip 的分享链接返回 404；页面无密钥泄露。（AC11、AC16）
