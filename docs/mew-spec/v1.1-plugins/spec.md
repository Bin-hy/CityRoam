# TripPilot v1.1 插件化技能 Spec

> 状态：已批准
> 基线：v1 MVP 已完成并通过 20/20 评测；本版只做增量，不回退已验收行为。

## 背景

v1 MVP 的规划主链是固定的：解析 → 检索 → 选点 → 调度 → 校验 → 修复 → 展示。它能稳定产出经过 C1–C12 校验的北京行程，但明确不支持酒店，也没有接入网页攻略；第三方能力只保留了 MCP 扩展位。

实际需求里，用户经常会：

- 已经定好酒店，希望行程围绕酒店位置安排；
- 给出总预算，希望住宿费用一起算进去；
- 希望参考小红书等平台的游玩攻略选点，而不是只看内置 POI。

这些能力不适合写死成新的固定分支。本版把它们封装成可配置启用的技能（Tool），由 LLM 在「技能研究阶段」自主决定调用时机与参数，再把结果交给现有确定性主链执行。主链仍然负责闭集选点、调度、校验和修复，避免把可靠性交给模型自由发挥。

## 目标

- 新增「技能研究阶段」：LLM 可在限定预算内自主调用已启用的外部技能。
- 接入酒店查询技能：支持用户指定酒店与系统推荐，提供位置、每晚价格、评分和来源。
- 接入攻略搜索技能：通过网页搜索获取小红书等公开攻略的标题、摘要、链接和权威度。
- 酒店与攻略结果能真实影响选点、预算和路线，同时保证候选闭集不被污染。
- 插件默认关闭；通过配置启用后自动注入 LLM 上下文，关闭时行为与 v1 完全一致。
- 保持可追踪、可评测、可降级：每次技能调用都有事件和证据，失败不拖垮主流程。

## 术语

- **技能（Skill / Tool）**：带名称、输入结构、输出结构和超时策略的外部能力，例如酒店查询、攻略搜索。
- **插件**：一组可配置启用的技能实现；本版包含酒店插件和攻略搜索插件。
- **研究阶段**：位于需求解析之后、候选检索之前的一个 LLM 工具调用阶段，产出结构化「研究提示」。
- **研究提示**：研究阶段交给主链的结构化结果，包括住宿选择、住宿对路线的建议、攻略提及点与证据。
- **证据**：带来源名称、来源链接、摘要和置信度的外部信息记录。

## 功能需求

- **F1 配置化启用**：酒店与攻略插件分别通过配置开启或关闭；未启用时技能不出现在 LLM 工具列表中，也不会发起任何外部调用。启用但缺少凭证或运行时依赖时，服务启动记录警告并自动禁用该插件，不阻塞主流程。
- **F2 技能自动注入**：每次运行开始时，系统将当前启用的技能及其输入结构注入 LLM 上下文；注入内容不包含任何密钥。技能集合变化后，下一次运行使用新集合，不需要改代码。
- **F3 LLM 自主工具调用**：研究阶段由 LLM 根据用户需求自主决定是否调用技能、调用哪个技能、用什么参数。系统只约束调用次数、超时、重试和白名单，不规定必须先查酒店还是先查攻略。
- **F4 酒店查询**：酒店技能接受城市、入住/退房日期、酒店名或关键词、价格上限、星级、床型、排序等条件，返回酒店名称、地址、坐标、每晚价格、评分、星级/类型、来源链接和预订链接。查询结果必须标注为估算或实时报价。
- **F5 指定酒店**：用户明确指定酒店名称时，系统优先按名称解析该酒店的位置和价格。若查不到、缺少坐标或拿不到价格，run 停在等待用户状态，展示已找到的相近酒店及原因，由用户确认改名或接受替代；不得静默替换，也不得把不确定价格计入预算。
- **F6 酒店触发条件**：只有需求解析识别到用户提及住宿（酒店、民宿、住宿、住哪里、指定酒店等）时，才允许调用酒店技能。未提及时不推荐酒店、不计住宿费用；若用户声称预算含住宿但没有住宿信息，研究阶段可以追问或按不含住宿处理，并在界面明确显示。
- **F7 住宿预算**：需求解析识别总预算是否包含住宿，默认包含，用户可在约束编辑区切换。行程为 N 天时按 N-1 晚计算住宿总价；含住宿时，住宿费用与门票、餐饮、交通一起受预算校验。价格统一标注为估算，不承诺实时库存。
- **F8 住宿影响路线**：研究阶段可产出住宿提示，例如推荐酒店、是否把酒店作为每天起点/终点、按距离加权的偏好。主链按提示机械化执行，不在代码中固定“必须每天回酒店”之类的策略。用户指定酒店时，该酒店位置优先作为选点和路线锚点。
- **F9 攻略搜索**：攻略技能通过公开网页搜索接口检索用户需求相关的内容，支持限定站点（如小红书）和普通网页。返回标题、链接、短摘要、长摘要、站点、发布时间和权威度；本版只读搜索结果，不抓取全文、不登录、不绕过站点限制。
- **F10 攻略影响选点**：从攻略结果中抽取被提及的地点名称，只匹配已有候选集内的 POI，并生成加权与解释；不得把无坐标或未校验的新地点加入候选，也不得覆盖必去点和硬约束。攻略摘要可作为选点提示词上下文，但外部文本必须按不可信内容处理。
- **F11 研究提示与主链衔接**：研究阶段输出结构化的住宿选择、住宿路线建议、攻略提及点、加权依据和证据列表。主链在选点时消费这些提示，在调度、校验、版本和分享中保留对应来源；研究阶段失败或超时则降级为无提示，主流程继续。
- **F12 可追踪与可回放**：每次技能调用记录技能名、参数摘要、耗时、重试次数、成功/失败、结果数量和来源；SSE 推送技能调用事件；版本中保存本次使用的住宿与攻略证据，回放时能看到当时依据。
- **F13 展示**：工作台新增「住宿建议」和「攻略参考」区域；住宿显示名称、位置、每晚价格、来源和估算标识；攻略显示标题、来源站点、摘要和可点击链接。用户切换“预算是否含住宿”后重新生成，旧版本保留。
- **F14 评测**：原有 20 条用例在插件关闭时必须保持既有行为；新增酒店、指定酒店、攻略加权和插件失败降级用例；评测报告区分插件开关状态。

## 非功能需求

- **N1 性能**：研究阶段总耗时目标 ≤12 秒；3 天行程端到端 p95 仍 ≤60 秒。单个技能超时 10 秒，重试 1 次；研究阶段最多 6 次技能调用。
- **N2 可靠性**：任一非指定酒店技能失败只降级为无提示，不使 run 失败；指定酒店无法解析时按 F5 进入等待；技能返回非法结构时按失败处理并记录原因。
- **N3 成本**：单次运行攻略搜索不超过 3 次、酒店查询不超过 2 次；重复查询命中缓存时不重复计费；单次规划模型成本仍 ≤0.5 元。
- **N4 安全**：酒店和搜索密钥只存在服务端环境变量；技能输入做长度与枚举校验；外部结果不得作为系统指令执行；工具白名单之外不可调用。
- **N5 合规**：只使用官方搜索/查询接口和公开摘要，不抓取需登录或禁止抓取的内容；酒店价格、库存和评分均标注来源与估算属性；攻略引用保留原始链接。
- **N6 可移植**：插件默认关闭；未安装酒店运行时依赖时服务仍可启动；Docker Compose 可通过配置决定是否启用插件。
- **N7 可观测**：技能调用、降级、追问、预算口径切换都有事件；错误分类可区分凭证、超时、限流、解析和业务空结果。
- **N8 兼容**：关闭插件时，解析、候选、调度、校验、版本、分享和评测行为与 v1 一致；现有数据库迁移不破坏旧数据。

## 不做的事

- 酒店、门票、机票的预订、支付和订单。
- 实时库存与价格保证；酒店价格只作估算。
- 抓取小红书全文、登录态内容、绕过反爬或未授权数据。
- 机票、火车票、跨城交通规划。
- 多城市、多人协作、账号体系。
- 把调度、校验、修复也交给 LLM 自由编排；本版主链仍保持确定性。
- 插件管理后台、运行时热插拔和可视化编排。
- 自动生成酒店评价总结或伪造用户评价。

## 验收标准

- **AC1**：默认配置下启动，酒店与攻略技能不可见、不发起调用，原 20 条评测结果与 v1 一致；关闭插件时行为不回退。
- **AC2**：开启酒店插件后，输入「北京三天，住全季酒店王府井店，预算 1500 含住宿」，研究阶段能调用酒店技能，行程围绕该酒店位置选点，预算包含 2 晚住宿。
- **AC3**：输入未提及住宿时不会调用酒店技能，也不产生住宿费用；用户可在约束编辑区切换“预算含住宿”并重新生成，旧版本保留。
- **AC4**：指定酒店查不到时，run 停在等待用户状态，展示相近酒店和失败原因；用户改名或接受替代后能继续，且不会把未知价格计入预算。
- **AC5**：酒店技能返回的价格、坐标、评分、来源链接进入住宿建议和版本证据；价格有估算标识。
- **AC6**：开启攻略插件后，输入「参考小红书攻略安排北京两天」，研究阶段能调用攻略搜索，返回带链接和摘要的来源；未启用的站点过滤条件不会被使用。
- **AC7**：攻略提到的地点只在已有候选集中匹配；匹配结果对选点产生可观察的加权或解释，候选集之外的地点不会进入行程；必去点和硬约束不被覆盖。
- **AC8**：攻略搜索超时或返回空结果时，行程仍能生成，trace 中有失败/降级事件，页面标明“攻略参考不可用”。
- **AC9**：SSE 能看到技能调用开始、完成/失败事件；版本详情能回放本次使用的酒店与攻略证据；分享页保留来源和 AI 标识。
- **AC10**：研究阶段最多 6 次技能调用、单技能超时 10 秒且重试 1 次；超过限制会停止并降级，不会无限调用。
- **AC11**：密钥不出现在前端、日志和仓库；外部摘要中的指令性文本不会改变系统行为；超长查询和非法参数被拒绝。
- **AC12**：新增酒店、指定酒店、攻略加权、失败降级用例可在评测中单独运行，报告区分插件开关状态。
