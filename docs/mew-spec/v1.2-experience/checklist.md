> 每一项通过运行代码、调用接口或观察页面来验证；验收时记录实际证据（命令输出、接口响应、界面观察），不记录预期值。

## A. 插件状态与降级（F1–F3）

- [ ] 酒店插件开关为 true 且 sidecar 健康时，`curl /api/meta` 返回 `plugins.hotels.enabled=true`，前端研究面板不再出现“住宿插件未启用”。（验证：开插件重启 API，curl + 打开页面观察）
- [ ] 关闭酒店插件后，`hotels.enabled=false` 且 `disabled_reason` 可读；面板显示该原因。（验证：改开关重启，对照 meta 与面板文字）
- [ ] 攻略开关 true、`GUIDE_SEARCH_API_KEY` 为空时，`guides.enabled=false` 且原因包含缺失项；补上 key 重启后变为 true。（验证：两次 curl 对比，不打印 key 值）
- [ ] 攻略超时或空结果时，行程照常生成，页面显示降级原因，正文没有编造的住宿或攻略引用。（验证：断网/伪造空响应跑一次，检查行程与面板）
- [ ] “未启用”的三种原因可区分：开关 false、密钥缺失、sidecar 不可达。（验证：分别构造三种环境，比较 `disabled_reason`）

## B. 拒绝改稿与取消（F4–F8）

- [ ] 初始方案等待确认时点“拒绝”，页面出现反馈输入框，run 仍为 `awaiting_user`（不是 `cancelled`）。（验证：UI 操作 + `GET /api/runs/{id}` 状态）
- [ ] 提交非空反馈后，同一个 run 产生新的调整提案；接受后生成新版本，`seq` 比基线 +1。（验证：记录 run ID 不变；版本列表对比）
- [ ] 提案等待确认时点“拒绝”，保留上一版本、状态回到 `awaiting_user`（stage=`proposal_rejected`），无 cancelled 事件。（验证：SSE 事件列表 + 页面版本内容）
- [ ] 提案拒绝后可直接输入新反馈并再次生成提案，无需刷新页面。（验证：连续两轮改稿）
- [ ] 空白反馈被拒绝并提示；2001 字符反馈被拒绝并提示；两者都不产生新 run 状态变化。（验证：API 400 + UI 提示；run 列表无新增）
- [ ] 点“取消规划”进入 `cancelled` 终态，并产生 `run.cancelled` 事件。（验证：UI + SSE 事件）
- [ ] 模拟调整失败（LLM/工具报错）时，原版本仍可查看；页面可直接再次提交反馈，不显示“运行已取消”。（验证：注入失败后检查版本与表单）

## C. 酒店解析与锚定（F9–F14）

- [ ] 点名酒店且 FlyAI 命中时，使用工具返回的价格与预订链接，`provider=flyai`。（验证：查看 plan.lodging 与预算）
- [ ] 关闭 FlyAI、仅配置 `AMAP_WEB_KEY` 时，指定酒店通过地理编码锚定，`provider=amap`，行程仍生成。（验证：plan.lodging + 时间轴）
- [ ] FlyAI 与 AMap 都不可用时，系统追问住宿选择，不静默地无锚定继续生成。（验证：清空两个配置后发起规划）
- [ ] 两天行程点名酒店后，每天首段为“从酒店出发”、末段为“返回酒店”；时间轴和地图显示酒店名称与位置。（验证：页面逐日检查 + 地图 marker）
- [ ] 用户明确“只住第 1 天”时，仅第 1 天首尾锚定，第 2 天不出现酒店首尾段。（验证：plan.lodging.anchor_days 与每日块）
- [ ] 仅地理编码、无房价时，预算不含住宿费，并出现“住宿费用未计入”警告；酒店仍作为锚点。（验证：totals 与 warnings）
- [ ] 有可信房价且预算包含住宿时，按 N-1 晚计入；用户显式排除住宿时预算不计。（验证：2 天/3 天行程各一次，对照 totals）

## D. 路线几何与地图（F15–F18）

- [ ] 接受版本的快照中，每条交通的 `legs` 包含方式、线路名（公交/地铁）、上下车站、时长、费用、折线坐标。（验证：查看 `GET /api/trips/{id}/versions/{seq}` 的 plan JSON）
- [ ] 折线满足上限：单段 ≤60 点、单日 ≤600 点；无腿数据时 `legs` 为空而非残缺对象。（验证：脚本统计所有 leg 点数）
- [ ] 地图按方式区分样式：步行虚线、公交实线、地铁另一色、驾车另一色；线路名可见。（验证：浏览器打开含公交/地铁的行程）
- [ ] 刷新页面与回放同一版本时，地图路线完全一致（不重新请求 AMap、不出现第二种画法）。（验证：刷新前后截图对比）
- [ ] 点击地图标记会选中对应时间轴块；点击时间轴块地图定位并弹出标题。（验证：双向点击）
- [ ] 无几何的旧版本快照渲染为灰色直线，无控制台报错，时间轴/预算不变。（验证：打开升级前生成的 trip）
- [ ] 模拟路径服务超时或未配置 AMap 时，路线回退直线并带估算标记（`estimated=true`），页面不空白。（验证：清空 `AMAP_WEB_KEY` 重启后规划）
- [ ] 酒店 marker 使用行程住宿坐标，参与自动缩放；无住宿时不渲染空 marker。（验证：有/无酒店两种行程）

## E. 集成与架构检查

- [ ] revise 后同一个 run ID 持续执行，`runs.mode` 在 DB 中为 `adjustment`；刷新页面后仍可继续等待/改稿。（验证：页面刷新 + 查库）
- [ ] 提案拒绝从 `plan_versions` 读取 `PreviousSeq` 对应版本恢复；不新增版本记录。（验证：拒绝前后版本列表长度不变）
- [ ] API 的 resume 响应状态来自实际 run 状态：提案 reject 返回 `awaiting_user`，无提案 legacy reject 返回 `cancelled`。（验证：两种请求对比）
- [ ] 无研究工具但存在指定酒店时，仍会调用地理编码（≤2 次）并完成锚定；无 resolver 时走提问。（验证：关闭 FlyAI 的两种配置）
- [ ] 插件状态由装配层规范名驱动：用真实 `WirePlugins` 输出构造 meta 时两个插件字段正确；未知名称不覆盖字段。（验证：`go test ./internal/api -run TestMeta`）
- [ ] 分段几何随快照持久化并能通过 SSE/回放读取；旧前端字段缺失时不抛异常。（验证：新行程接口 + 旧构建页面冒烟）
- [ ] 无 DDL 变更：全新库与旧库都能启动，旧数据无需迁移。（验证：对旧库直接启动；`migrations` 无新增文件）
- [ ] 旧环境文件可直接启动；缺少 FlyAI/攻略/AMap 配置时按预期降级并给出原因。（验证：用升级前的 `.env` 启动）

## F. 编译、测试与性能

- [ ] `gofmt -l .` 输出为空；`go vet ./...` 通过。（验证：执行命令）
- [ ] `make test`（`go test -race ./...`）全绿。（验证：执行并记录通过包数）
- [ ] `cd web && npm test` 全绿；`npm run build` 成功。（验证：执行并记录测试数量）
- [ ] `make eval` 中 20 条 v1 用例与 v1.1 插件评测通过率不下降。（验证：与基线报告逐项对比）
- [ ] 排期 p95 增幅 ≤10%。（验证：评测报告耗时对比）
- [ ] 单版本快照体积 ≤100KB，且相对基线的增幅 ≤100KB。（验证：统计 `plan_versions.plan` 字节数）
- [ ] 新增依赖为零：`go.mod`、`package.json` 无新增项。（验证：git diff）

## G. 端到端场景

- [ ] 场景 1（改稿闭环）：创建 2 天行程 → 等待确认 → 拒绝 → 输入“第二天下午轻松一点” → 同 run 出新提案 → 接受 → 版本 seq+1，时间轴与地图同步更新。（验证：浏览器全程操作 + 版本接口）
- [ ] 场景 2（酒店锚定）：FlyAI 关闭、配置 AMap，输入“我住北京饭店” → 每天首尾为酒店、地图有酒店标记、预算出现未计住宿 warning → 再次输入“只住第 1 天”的新行程，仅第 1 天锚定。（验证：两次规划对照）
- [ ] 场景 3（地图兼容）：打开一条新行程（分段着色）与一条旧行程（虚线），刷新、回放、点击标记均正常。（验证：浏览器对照）
- [ ] 场景 4（失败恢复）：攻略超时 + 路径服务不可用 → 行程仍生成并显示降级原因/估算标记；调整阶段注入失败 → 原版本可查看且可再次提交反馈。（验证：故障注入后操作）
- [ ] 场景 5（插件矩阵）：hotel/guide 开/关四种组合下，`/api/meta` 与前端提示一致，行程均能生成或明确降级。（验证：四组 curl + 页面）
