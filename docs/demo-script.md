# TripPilot 3 分钟演示脚本

目标：在 3 分钟内讲清「LLM 选点 + 确定性校验 + 修复 + 调整 + 分享」的闭环，并给出可验证的评测数据。

## 演示前检查（不计入 3 分钟）

```sh
# 后端
set -a; . ./.env.local; set +a
go run ./cmd/api

# 前端
cd web && npm run dev

# 数据库与 LLM/高德 Key 已配置；浏览器打开 http://localhost:5173
```

- 确认 `/healthz` 返回 200。
- 预热一次生成，避免首次 LLM 调用过慢。
- 若现场网络不稳定，提前打开一次真实行程页面作为兜底。

## 时间线

### 0:00–0:30 开场：问题与定位

讲解点：

- 旅行规划不是「写一篇攻略」，而是多约束排程：营业时间、闭馆日、路程、预算、用餐、必去点、节奏。
- LLM 擅长选点和叙事，不擅长算术与硬约束；TripPilot 让 LLM 只从候选 POI 中选，时间、路程、费用、校验全部由确定性代码完成。
- 首版聚焦北京 1～4 天，目标是可演示、可评测、可部署。

### 0:30–1:10 生成与校验

操作：

1. 在首页「行程需求」输入：`北京两天，历史与博物馆，预算 800 元，必去故宫`。
2. 点击「开始规划」，进入 `/trips/:id`。

预期：

- 右侧事件流依次出现：解析约束 → 检索候选 → 草稿 → 排程 → 校验。
- 时间轴出现两天行程，地图标注 POI；预算卡片显示总费用。
- 若出现违规，列表标出阻断项（红）与警告项（黄）。

讲解点：

- 候选 POI 来自工具，草稿只能返回候选中的 ID；未知 ID 直接失败。
- 校验是 C1–C12 的确定性规则，不依赖模型自觉。
- 有阻断项时自动进入 repair，只重写受影响的那一天，最多 3 轮；事件流能看到每轮修复。

### 1:10–1:50 调整与版本

操作：

1. 点击「接受方案」。
2. 在「调整需求」输入：`第二天下午轻松一点，少走路`。
3. 点击「提交调整」，等待「调整提案」出现。
4. 点击「接受调整」。

预期：

- 提案展示变更范围、费用/步行变化和警告，不直接改方案。
- 接受后生成新版本，时间轴与预算更新；旧版本保留在历史中，可回滚。

讲解点：

- 调整先提案、后接受，避免模型直接覆盖用户已确认的方案。
- 版本只追加；接受新版本会把旧版本标记为 superseded，回滚是复制旧版本为新序号。
- 每次运行的事件可按 `seq` 回放，SSE 断线可用 `Last-Event-ID` 续传。

### 1:50–2:20 分享与降级

操作：

1. 点击「分享」。
2. 复制「分享链接」，新标签页打开 `/share/:slug`。

预期：

- 只读页面展示已接受版本，提供纯文本导出。
- 未配置高德 JS Key 时，地图区域显示「地图暂不可用」和配置提示，不影响时间轴与方案阅读。

讲解点：

- 分享使用随机 slug，不暴露内部 trip/run ID。
- 外部依赖失败时降级：高德不可用则回退内嵌 POI 快照与直线距离估算，并在页面标注。

### 2:20–3:00 评测与收尾

操作：

1. 打开 `/eval`，输入管理员令牌，点击「进入评测面板」。
2. 展示 20 条用例、硬约束满足率、平均修复轮数、p95 延迟、POI/JSON 有效率。
3. 点开一条失败或高修复轮次的用例，说明定位方式（事件流 + violations）。

讲解点：

- 20 条固定用例覆盖 1～4 天、预算、节奏、必去点、闭馆日、雨天与冲突。
- 指标目标：硬约束满足率 ≥90%，JSON 合法率 ≥99%，3 天 p95 ≤60s。
- 当前结果见 `docs/eval-report.md`；失败用例保留原因，不隐藏。
- 工程侧：Go + Eino、PostgreSQL、SSE、React 19、Docker Compose + Caddy；单机可部署，密钥只留在服务端。

## 现场兜底

| 风险 | 处理 |
|---|---|
| LLM 超时 | 缩短输入为「北京一天，经典景点」，或展示预热好的行程 |
| 高德配额/网络失败 | 说明自动降级到内嵌快照，继续演示时间轴与校验 |
| 调整提案过慢 | 跳过调整，直接展示已生成的版本历史与分享页 |
| 评测接口 401/503 | 说明 `ADMIN_TOKEN` 或评测服务未配置，改展示 `docs/eval-report.md` |

## 一句话收尾

「模型负责创意，代码负责正确性；每次生成、修复、调整都可回放、可评测、可部署。」
