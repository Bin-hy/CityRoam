## 1. 设计目标与边界

**目标**

- 可执行：营业时间、路程、预算、体力都成立。
- 可解释：每个安排有来源，每次修改有 diff。
- 可调整：改一句话只重排受影响范围。
- 可交付：单人、60 小时、单机部署。

**边界**

- 首版只做北京，1～4 天。
- 不做预订、支付、酒店、机票、实时公交、多城市。
- 不做账号体系、多人协作、原生 App。
- 不做高可用、多地域、K8s、多租户。

## 2. 使用对象与部署对象

### 2.1 使用对象

| 对象 | 场景 | 访问方式 |
|---|---|---|
| 旅行者 | 创建、调整、导出行程 | 匿名 trip ID |
| 分享访客 | 只读查看行程 | 随机 share slug |
| 评测者 | 跑用例、看 trace | 内部接口 + token |
| 运维者 | 部署、备份、排障 | SSH / 日志 / 健康检查 |

### 2.2 部署对象

| 对象 | 形态 | 暴露范围 | 职责 |
|---|---|---|---|
| Browser SPA | 静态资源 | 公网 443 | 创建页、工作台、分享页 |
| Caddy | 容器 | 公网 443 | TLS、静态资源、反向代理 |
| Go API | 单二进制容器 | 内网 8080 | REST、SSE、Eino Graph |
| PostgreSQL | 容器 + volume | 内网 5432 | 唯一持久化存储 |
| MCP Server | 容器 / 子进程 | 内网 | 第三方能力（搜索、小红书） |
| LLM API | 外部 SaaS | 出网 | 解析、生成、解释 |
| 高德 API | 外部 SaaS | 出网 | POI、路径、天气 |
| CI/CD | GitHub Actions | 出网 | 构建、测试、发布 |

## 5. 前端客户端选型

### 5.1 结论

**React 19 + Vite + TypeScript + shadcn/ui + assistant-ui + 高德 JS + vis-timeline + TanStack Query。**

### 5.2 选型理由

| 维度 | 选择 | 理由 |
|---|---|---|
| 框架 | React 19 + Vite | 生态最大，无 SSR 需求，静态构建简单 |
| UI | Tailwind + shadcn/ui | 组件可控、体积小、不绑定主题 |
| 聊天/轨迹 | assistant-ui | Thread、Composer、工具卡片齐全，支持 external store 接 SSE |
| 数据请求 | TanStack Query | 缓存、重试、失效，避免手写请求层 |
| 地图 | 高德 JS（MVP） | 与后端 GCJ-02 对齐，北京 POI 精度最好 |
| 地图备选 | Leaflet + OSM + gcoord | 全开源，但需坐标转换，OSM 国内细节较弱 |
| 时间轴 | vis-timeline | 缩放、拖拽、只读模式都支持 |
| 版本 diff | jsondiffpatch + react-diff-viewer-continued | JSON 语义差异，不自己写 diff |
| 流式 | EventSource / fetch-event-source | SSE 足够，不需要 WebSocket |
| 测试 | Vitest + Playwright（可选） | 组件测试 + 关键路径 E2E |

**不选 Next.js**：没有 SSR/SEO 需求，分享页 OG 可后补；少一个 Node 运行时。
**不选 CopilotKit**：更重，绑定自己的 runtime；assistant-ui 已覆盖聊天和工具卡片。
**不选 Ant Design / MUI**：shadcn/ui 更可控，Tailwind 更适合定制三栏工作台。

### 5.3 页面结构

```
/                 创建页：一句话输入、示例、高级选项
/trips/:id        工作台：左轨迹 / 中地图+时间轴 / 右预算+解释+版本
/share/:slug      分享页：只读行程、地图、预算、AI 标识
/eval             评测面板：内部使用，token 保护
```

移动端：三栏纵向堆叠；地图和时间轴可切换 Tab。

## 8. 部署架构与范围

### 8.1 环境

| 环境 | 用途 | 依赖 |
|---|---|---|
| local | 开发、单测、CLI | 本地快照、mock LLM、docker compose |
| demo | 公网演示 | 真实 LLM、高德、2C4G VPS |
| prod（可选） | 长期在线 | 同 demo，加备份和限流 |

### 8.2 拓扑

```
Internet
  │ 443
Caddy
  ├─ /        → SPA 静态资源
  └─ /api/*   → Go API:8080
                 ├─ postgres:5432（仅内网）
                 └─ mcp-*（仅内网）
                        │
                   LLM / 高德（出网）
```

- 只暴露 80/443；Postgres、MCP 不对外。
- 单实例运行；SSE 在进程内。
- 卷：`pgdata`、`caddy_data`。
- 备份：每日 `pg_dump`，保留 7 天。
- 发布：GitHub Actions 构建镜像 → GHCR → SSH `compose pull` + `up -d`。
- 迁移：部署前执行 `goose up`。
- 密钥：GitHub Secrets / 服务器 `.env`，不进镜像。

### 8.3 部署范围

**包含**

- 单地域、单节点、单实例。
- 公网 Web + 分享页。
- 匿名使用 + IP 限流。
- 内部评测接口。

**不包含**

- 多地域、多可用区、自动扩缩容。
- K8s、服务网格、跨服务 RPC。
- 多租户、账号体系、团队协作。
- 原生 App、离线模式。

### 8.4 扩展路径

| 阶段 | 变化 |
|---|---|
| 单实例 | 当前方案 |
| 多实例 | API 无状态化；SSE 改用 Postgres `LISTEN/NOTIFY` |
| 多城市 | 增加 POI 快照和城市配置，不改核心 |
| 高可用 | 托管 Postgres + 负载均衡 + 共享缓存 |

## 9. 数据与存储

| 表 | 作用 |
|---|---|
| `trips` | 规划任务 |
| `plan_versions` | 行程版本 |
| `runs` | 一次 plan/replan 执行 |
| `run_events` | 步骤、工具、校验事件 |
| `tool_calls` | native / MCP 调用记录 |
| `evidence` | 外部证据与来源 |
| `poi_cache` | 北京 POI 快照 |
| `plugin_cache` | 外部结果缓存 |
| `share_links` | 分享链接 |
| `eval_runs` | 评测结果 |

- POI 快照以 JSON 种子导入，带版本和核对日期。
- 不存图片、视频；无对象存储。
- 行程删除后保留 7 天；工具调用保留 30 天；评测长期保留。

## 10. 关键流程

**首次规划**

```
POST /api/trips
  → 创建 trip + run
  → parse → retrieve → draft → validate → repair
  → 保存 plan_version
  → SSE 全程推送
```

**调整**

```
POST /api/trips/{id}/adjustments
  → 解析意图与影响范围
  → 新建 replan run
  → 只重排受影响的天/时间块
  → 新版本 + diff
```

## 11. 非功能设计

| 类别 | 设计 |
|---|---|
| 性能 | 解析 ≤5s；3 天行程 p95 ≤60s；SSE 每 2s 心跳 |
| 可靠性 | 工具超时 10s、重试 2 次；LLM 60s；修复最多 3 轮 |
| 成本 | 单次 LLM ≤0.5 元；POI/路径缓存 |
| 安全 | 密钥服务端；IP 限流；MCP 白名单；分享 slug 随机 |
| 可观测 | OTel + 结构化日志 + `run_events` 回放 + `/healthz` |
| 可移植 | Docker Compose；配置全走环境变量 |
