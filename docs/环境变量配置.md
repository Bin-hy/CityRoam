# 环境变量配置指南（.env.local）

本文说明本地开发时 `.env.local` 如何配置、各变量含义与失败表现。内容以当前代码为准（`internal/config/config.go`、`cmd/api/main.go`、`deploy/docker-compose.yml`、`web/vite.config.ts`），最后核对日期：2026-11-20。

---

## 1. 先理解加载规则

`.env.local` 只是一个普通文本文件，**任何程序都不会自动读取它**。四个端各有自己的规则：

| 端 | 如何拿到变量 | 注意事项 |
|---|---|---|
| Go API / 评测 / 种子命令 | 只读进程环境（`os.Getenv`），没有 dotenv 依赖 | 启动前必须手动 export，见下方命令 |
| Vite 开发服务器 | 读取 `web/` 目录下的 `.env*`，同时承认已 export 的 `VITE_*` | 根目录 `.env.local` **不会**被 Vite 自动读取 |
| Docker Compose | 读取 `deploy/.env`（Compose 的项目目录） | 根目录 `.env.local` 不参与 Compose |
| 前端生产构建 | `deploy/.env` → build args → 打进 `web/dist` | 构建期固化，改完要重新构建 |

本地启动 API 的标准姿势：

```sh
set -a
. ./.env.local
set +a
go run ./cmd/api
```

`set -a` 让 source 进来的变量自动导出；少了它，变量只存在于当前 shell，子进程（`go run`）看不到。`make test` / `make eval` 同样不会加载该文件，需要先在同一个 shell 里 export。

含空格的值（如 `OIDC_SCOPES="openid profile email"`）必须加引号，否则 `source` 会把后半段当命令执行。`.env.example` 已按可直接 source 的写法维护，可作为模板复制。

Vite 开发时推荐在 `web/.env.local` 单独放前端变量：

```sh
# web/.env.local（已被 .gitignore 忽略）
VITE_AMAP_JS_KEY=...
VITE_AMAP_SECURITY_CODE=...
```

也可以在同一 shell 先 export 再 `npm run dev`，但独立文件更不容易漏。

> `.gitignore` 已忽略 `.env`、`.env.*` 和 `*.local`，仅 `.env.example` 入库。不要把真实 key 提交到仓库。

## 2. 模板默认值一览（`.env.example`）

| 变量 | 模板默认 | 说明 |
|---|---|---|
| `DATABASE_URL` | 本地 Postgres 占位串 | 必须改成可连接的 DSN |
| `PORT` / `LOG_LEVEL` | `8080` / `info` | 可直接使用 |
| `LLM_BASE_URL` / `LLM_MODEL` | `https://api.deepseek.com` / `deepseek-chat` | `LLM_API_KEY` 必须填写 |
| `AMAP_WEB_KEY` | 空 | 为空时无实时 POI、无天气工具，主链仍可跑 |
| `VITE_AMAP_JS_KEY` / `VITE_AMAP_SECURITY_CODE` | 空 | 为空时地图卡片显示降级提示 |
| `ADMIN_TOKEN` | 空 | 评测接口会一律 401 |
| `RATE_LIMIT_PER_HOUR` | `10` | 仅写接口 |
| `HOTEL_PLUGIN_ENABLED` / `GUIDE_PLUGIN_ENABLED` | `false` / `false` | 与代码默认一致，开启前需备好依赖 |
| `HOTEL_TOOL_TOKEN` / `GUIDE_SEARCH_API_KEY` / `FLYAI_API_KEY` | 空 | 仅开启对应插件时需要 |
| `HOTEL_*` / `GUIDE_*` / `RESEARCH_*` | `10s` / `30m`、`10s` / `6h`、`12s` / `6` | 可直接使用 |
| `WEATHER_CACHE_TTL` / `WEATHER_TOOL_TIMEOUT` / `WEATHER_MAX_CALLS_PER_RUN` | `30m` / `3s` / `1` | `AMAP_WEB_KEY` 非空即启用天气工具 |
| `AUTH_ENABLED` | `false` | 默认关闭，保持 demo 匿名流程 |
| `OIDC_*` / `ADMIN_EMAILS` / `ADMIN_SUBS` / `CORS_ALLOWED_ORIGINS` | 空 | 仅在启用登录时需要 |

结论：复制模板后至少填好 `DATABASE_URL`、`LLM_API_KEY`，主链（生成、校验、修复、分享、调整、版本）即可运行；地图与天气取决于 `AMAP_WEB_KEY`，插件默认关闭，评测管理接口需要 `ADMIN_TOKEN`，登录默认关闭。

`LLM_MODEL` 必须确认 provider 确实提供该模型名；DeepSeek 官方常用的是 `deepseek-chat` / `deepseek-reasoner`，模型名错误会在第一次 LLM 调用时以 4xx 失败并让 run 进入 `failed`。

## 3. 变量逐项说明

### 3.1 数据库与服务

| 变量 | 必填 | 默认 | 格式 | 说明 |
|---|---|---|---|---|
| `DATABASE_URL` | 是 | 无 | Postgres DSN | 为空时启动直接报 `DATABASE_URL is required`。API 启动会自动执行 goose 迁移，无需单独 migrate |
| `PORT` | 否 | `8080` | 1–65535 整数 | 非法值启动报错；健康检查默认也访问 `127.0.0.1:8080/healthz` |
| `LOG_LEVEL` | 否 | `info` | `debug`/`info`/`warn`/`error` | 非法值启动报错 |
| `HEALTHCHECK_URL` | 否 | `http://127.0.0.1:8080/healthz` | URL | 只被容器内的 `healthcheck` 程序使用，本地开发不用配 |

本地数据库最小启动方式（README 同款）：

```sh
docker run -d --name trippilot-pg \
  -e POSTGRES_USER=trippilot -e POSTGRES_PASSWORD=trippilot -e POSTGRES_DB=trippilot \
  -p 5432:5432 postgres:16
# DATABASE_URL=postgres://trippilot:trippilot@localhost:5432/trippilot?sslmode=disable
```

`make seed`（`cmd/seed`）会把 `data/poi/beijing.json` 写入 `poi_cache`，属于可选的运维步骤；主流程使用编译期内嵌快照，不依赖这张表。

### 3.2 LLM（OpenAI 兼容）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `LLM_BASE_URL` | 是 | 无 | 不允许为空，否则启动报 `LLM_BASE_URL and LLM_MODEL are required`。客户端会自动追加 `/chat/completions`；若你的服务要求 `/v1`，就把 base 写成 `https://host/v1` |
| `LLM_API_KEY` | 实际必填 | 无 | 允许为空启动，但所有 LLM 调用会 401，run 以 `failed` 结束。它同时被研究阶段的工具调用复用 |
| `LLM_MODEL` | 是 | 无 | 传给 Chat Completions 的模型名；必须是 provider 支持的名称 |

主链只用一次结构化生成（`GenerateJSON` + JSON Schema），研究阶段用 `CompleteWithTools`；两者共用这一组变量。温度、超时等参数当前不可通过环境变量配置，超时在代码中固定（默认 60s）。

### 3.3 高德地图

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `AMAP_WEB_KEY` | 否 | 空 | 后端「Web 服务」类型 key。为空时：不接入高德 POI 搜索，路程回退直线距离（haversine），天气工具被禁用；主链仍可运行 |
| `VITE_AMAP_JS_KEY` | 否 | 空 | 前端「Web 端 (JS API)」key，构建期注入。为空时地图卡片显示「未配置 VITE_AMAP_JS_KEY」降级提示 |
| `VITE_AMAP_SECURITY_CODE` | 否 | 空 | JS API 2.0 安全密钥，必须与 JS key 配套 |

两个 key 是不同类型，需要分别在高德控制台申请并配置域名白名单。坐标统一为 GCJ-02，不要与 WGS-84 混用。

`VITE_*` 会被打进浏览器 bundle：只能是受限的 JS key，**绝不能**放 `AMAP_WEB_KEY`、`LLM_API_KEY` 或任何服务端密钥。

### 3.4 限流与运维

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `RATE_LIMIT_PER_HOUR` | 否 | `10` | 范围 1–1,000,000。固定一小时窗口，只作用于写接口：创建行程、删除、调整、replan、恢复版本、分享、resume、cancel；GET 与 SSE 不受限。登录启用后按用户 ID 计数，未登录回退到 IP |
| `ADMIN_TOKEN` | 否 | 空 | 保护 `/api/eval/*`。为空时所有请求返回 **401**（不是 503）。请求头可用 `X-Admin-Token: <token>` 或 `Authorization: Bearer <token>` |

### 3.5 研究插件总开关与研究循环

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `HOTEL_PLUGIN_ENABLED` | 否 | `false` | 代码与 `.env.example` 默认均为关闭；确认 sidecar 可用后再改为 `true` |
| `GUIDE_PLUGIN_ENABLED` | 否 | `false` | 同上 |
| `RESEARCH_TIMEOUT` | 否 | `12s` | 研究阶段总时限，必须是正数 duration（如 `8s`、`500ms`）；超时后降级为短 brief，不阻断主链 |
| `RESEARCH_MAX_TOOL_CALLS` | 否 | `6` | 1–100 的整数，研究阶段工具调用上限 |
| `SKILLS_DIR` | 否 | `skills` | 版本化技能目录；不存在时按无技能启动。结构与锁文件规则见 [Agent Skills](skills.md) |

两个插件都关闭时：不探测外部服务、不注入研究工具，主链与 v1 评测结果不受影响。

插件状态名与 `/api/meta` 字段一一对应，不要混用：

| 代码内部规范名 | `/api/meta` 字段 | 前端展示 |
|---|---|---|
| `hotel` | `plugins.hotels` | 住宿（飞猪 / FlyAI sidecar） |
| `guide` | `plugins.guides` | 攻略（DeepSeek WebSearch 摘要） |
| `weather` | `plugins.weather` | 天气（高德实时天气，无独立开关） |

前端显示“未启用”时，按以下顺序对应到 `disabled_reason`：

1. 开关为 false：`HOTEL_PLUGIN_ENABLED` / `GUIDE_PLUGIN_ENABLED` 未开，插件不会加载。
2. 开关为 true 但配置缺失：如 `GUIDE_SEARCH_API_KEY is empty`、`HOTEL_TOOL_URL is empty`。
3. 依赖不可达：如 `hotel tool health check failed`，通常是 sidecar 未启动、URL 写错或健康检查超时。

启用后自检（两步）：

1. `curl -s localhost:8080/api/meta | jq '.plugins'`，确认目标插件 `enabled: true` 且没有 `disabled_reason`；`hotels` 对应住宿，`guides` 对应攻略，`weather` 对应天气。
2. 刷新工作区的研究面板或插件状态提示，确认“未启用”文案及其原因消失；若原因仍在，按 `disabled_reason` 回到 3.6 / 3.7 排查。

### 3.6 酒店插件（FlyAI sidecar）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `HOTEL_TOOL_URL` | 开启时必填 | 代码默认 `http://hotel-tool:8090` | 本地应写 `http://127.0.0.1:8090`；Compose 内应写 `http://hotel-tool:8090` |
| `HOTEL_TOOL_TOKEN` | 否 | 空 | API 调 sidecar 的 Bearer token；sidecar 用同一变量校验。为空表示不鉴权，只适合本机或 Compose 内网 |
| `HOTEL_SEARCH_TIMEOUT` | 否 | `10s` | 单次酒店搜索超时 |
| `HOTEL_CACHE_TTL` | 否 | `30m` | 酒店结果缓存时间 |
| `FLYAI_API_KEY` | sidecar 必填 | 空 | 只给 sidecar，不进 API 进程 |
| `FLYAI_BIN` | 否 | `flyai`（Compose 内为 `/app/node_modules/.bin/flyai`） | sidecar 调用的 FlyAI CLI 路径 |
| `FLYAI_TIMEOUT_MS` | 否 | `9000` | sidecar 调用 FlyAI CLI 的单次超时（毫秒），Compose 会透传 |
| `FLYAI_HEALTH_TIMEOUT_MS` | 否 | `1500` | sidecar 启动自检 / 健康探测超时（毫秒） |

启用条件（任一不满足就只禁用该插件，不影响启动）：开关为 true、URL 非空、启动时 `/healthz` 探测 1s 内成功。失败原因可在 `GET /api/meta` 的 `plugins.hotels.disabled_reason` 看到，例如 `hotel tool health check failed`。

关闭酒店插件但配置了 `AMAP_WEB_KEY` 时，用户明确指定的酒店仍会通过高德地理编码锚定：解析成功则作为每天行程的起终点，价格为 0、`price_estimated: true`，预算中标记 warning 且 `include_in_budget: false`；只有解析失败时才询问用户或默认锚定。FlyAI sidecar 不是酒店锚定的必要条件。

本地顺序：先起 sidecar，再起 API。

```sh
cd deploy/hotel-tool
npm ci --omit=dev
PORT=8090 FLYAI_BIN="$PWD/node_modules/.bin/flyai" npm start
```

### 3.7 攻略插件（搜索摘要）

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `GUIDE_SEARCH_BASE_URL` | 否 | `https://api.deepseek.com` | 代码固定拼接 `/v1/tools/search`，base 不要重复带 `/v1` |
| `GUIDE_SEARCH_API_KEY` | 开启时必填 | 空 | 为空时插件被禁用，原因 `GUIDE_SEARCH_API_KEY is empty` |
| `GUIDE_SEARCH_TIMEOUT` | 否 | `10s` | 单次攻略搜索超时 |
| `GUIDE_CACHE_TTL` | 否 | `6h` | 攻略结果缓存时间 |

攻略结果只用于给已有候选 POI 加权，不会新增 POI；外部摘要按不可信内容处理。

### 3.8 天气研究工具

天气工具没有独立开关：`AMAP_WEB_KEY` 非空时自动注册为 `get_weather`；为空时启动日志会打印 `research plugin disabled plugin=get_weather reason=AMAP_WEB_KEY is empty`，`GET /api/meta` 的 `plugins.weather` 也会给出 `enabled: false` 与 `disabled_reason`。

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `WEATHER_CACHE_TTL` | 否 | `30m` | 按城市缓存的天气结果有效期 |
| `WEATHER_TOOL_TIMEOUT` | 否 | `3s` | 单次高德天气请求超时，超时视为该次查询失败 |
| `WEATHER_MAX_CALLS_PER_RUN` | 否 | `1` | 单次研究运行的天气调用上限，范围 1–10 |

### 3.9 前端构建

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `VITE_API_BASE` | 否 | 空（同源） | 仅当 API 与前端不同源时设置。本地 Vite 已代理 `/api`、`/healthz`、`/readyz` 到 `http://localhost:8080`，无需配置 |
| `API_PROXY_TARGET` | 否 | `http://localhost:8080` | Vite 配置读取的是 Node 进程环境（不带 `VITE_` 前缀），用于改代理目标 |
| `WEB_PORT` | 否 | Vite 默认 5173 | 同上，Node 进程环境 |

Docker 构建时，`VITE_AMAP_JS_KEY` / `VITE_AMAP_SECURITY_CODE` 由 `deploy/.env` 作为 build args 传入并固化进静态资源；修改后必须重新 `--build`。

### 3.10 用户登录与角色（OIDC）

登录默认关闭（`AUTH_ENABLED=false`），关闭时保持匿名 demo 流程：无 Cookie 要求，行程列表返回无主数据，分享页照常公开。开启后必须登录才能创建或查看行程。

| 变量 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `AUTH_ENABLED` | 否 | `false` | 设为 `true` 时强制登录；四个 OIDC 必填项缺一启动即报错 |
| `OIDC_ISSUER` | 开启时必填 | 空 | IdP issuer，用于 discovery（`/.well-known/openid-configuration`），必须是 http/https URL |
| `OIDC_CLIENT_ID` | 开启时必填 | 空 | 在 IdP 注册的 Web 应用 client id |
| `OIDC_CLIENT_SECRET` | 开启时必填 | 空 | 仅存在于服务端环境变量；不写库、不下发浏览器、不写日志 |
| `OIDC_REDIRECT_URI` | 开启时必填 | 空 | 必须与 IdP 注册值完全一致，例如 `http://localhost:8080/api/auth/callback` |
| `OIDC_SCOPES` | 否 | `openid profile email` | 空格分隔；至少包含 `openid` |
| `OIDC_AUDIENCE` | 否 | 空 | 非空时额外校验 access token 的 audience。填 access token 的资源 audience（yufu 形如 `urn:yufu:<project-id>:<env>:api`），不是 client id 或应用名；只用 ID token 做登录时留空即可 |
| `OIDC_PROVIDER_NAME` | 否 | `统一登录` | 登录页展示的提供方名称 |
| `OIDC_POST_LOGOUT_REDIRECT_URI` | 否 | 空 | IdP 支持 end-session 时退出后的回跳地址 |
| `AUTH_WEB_BASE_URL` | 否 | 空 | 同源部署留空；前后端分离时填 Web 源，回调后跳回该地址 |
| `AUTH_SESSION_TTL` | 否 | `168h` | 服务端会话绝对有效期 |
| `AUTH_COOKIE_SECURE` | 否 | `auto` | `auto` 在 TLS 或 `X-Forwarded-Proto=https` 时加 Secure；也可强制 `true`/`false` |
| `ADMIN_EMAILS` | 否 | 空 | 逗号分隔；命中且 `email_verified=true` 时授予 admin |
| `ADMIN_SUBS` | 否 | 空 | 逗号分隔的 subject，精确匹配授予 admin |
| `CORS_ALLOWED_ORIGINS` | 否 | 空 | 逗号分隔的完整源（含 scheme），不允许 `*`；分离部署时必须包含 Web 源 |

角色规则：yufu 等 IdP 只负责认证，TripPilot 自己授权。默认角色是 `user`；`admin` 仅用于 `/api/eval/*`，不能查看其他用户的行程。`ADMIN_TOKEN` 仍保留，用于脚本和紧急访问。

Cookie 与请求：

- 会话 Cookie 名 `trippilot_session`，HttpOnly、SameSite=Lax；浏览器只持有不透明随机串，数据库存 SHA-256 哈希。
- 登录临时绑定 Cookie 名 `trippilot_oidc`，Path `/api/auth`，10 分钟过期，用于校验 state。
- 前后端分离时前端请求必须带凭据（本项目客户端已设置 `credentials: "include"`），服务端需配置 `CORS_ALLOWED_ORIGINS`。
- 开启登录后，写请求会校验 `Origin` 与 `Host` 同源。本地用 Vite 代理（5173 → 8080）时两者不一致，需要在 API 进程设置 `CORS_ALLOWED_ORIGINS=http://localhost:5173`（端口换成你的 `WEB_PORT`），否则创建行程、调整、分享等 POST 会返回 `403 请求来源不被允许`。Compose 内由 Caddy 代理并保留 Host，无需额外配置。

若使用本地 yufu 作为 IdP：以 yufu 的实际 issuer 填写 `OIDC_ISSUER`（通常形如 `http://127.0.0.1:9410`），在 yufu 注册 Web 应用，回调填 `OIDC_REDIRECT_URI`，拿到 client id/secret。具体注册命令以 yufu 当前版本文档为准。

## 4. 场景配方

**A. 最小可跑（生成主链）**

```ini
DATABASE_URL=postgres://trippilot:trippilot@localhost:5432/trippilot?sslmode=disable
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=<你的 key>
LLM_MODEL=deepseek-chat
```

**B. A + 地图、实时 POI 与天气**

```ini
AMAP_WEB_KEY=<Web 服务 key>
VITE_AMAP_JS_KEY=<JS API key>
VITE_AMAP_SECURITY_CODE=<安全密钥>
```

**C. B + 酒店研究**

```ini
HOTEL_PLUGIN_ENABLED=true
HOTEL_TOOL_URL=http://127.0.0.1:8090
HOTEL_TOOL_TOKEN=<可选，与 sidecar 保持一致>
FLYAI_API_KEY=<sidecar 使用的 key>
```

**D. B + 攻略研究**

```ini
GUIDE_PLUGIN_ENABLED=true
GUIDE_SEARCH_BASE_URL=https://api.deepseek.com
GUIDE_SEARCH_API_KEY=<搜索接口 key>
```

**E. 开评测管理接口**

```ini
ADMIN_TOKEN=<足够长的随机串>
```

**F. 评测 CLI**

`go run ./cmd/eval` 与 API 共用 `config.Load`，至少需要 `DATABASE_URL`、`LLM_*`；插件评测再加 `-plugins` 及对应插件变量。`--dry-run` 只读用例，不调用 LLM。

**G. Docker Compose**

把上述变量写进 `deploy/.env`（不是根目录 `.env.local`）：

```sh
cp .env.example deploy/.env
# 编辑 deploy/.env
make dev
```

## 5. 启动后自检

```sh
# 进程与数据库
curl -s localhost:8080/healthz
curl -s localhost:8080/readyz

# 当前限流与插件状态（不泄露密钥）
curl -s localhost:8080/api/meta | jq '{version, rate_limit, plugins}'

# 评测接口鉴权
curl -s -o /dev/null -w '%{http_code}\n' localhost:8080/api/eval/cases
curl -s -H "X-Admin-Token: $ADMIN_TOKEN" localhost:8080/api/eval/cases

# 登录状态（关闭时应返回 enabled=false；开启且未登录时应返回 authenticated=false）
curl -s localhost:8080/api/auth/me | jq '{enabled, authenticated, provider_name}'
```

`/api/meta` 的 `plugins.hotels` / `plugins.guides` / `plugins.weather` 会给出 `enabled` 与 `disabled_reason`，是排查插件为什么没生效的第一站。

## 6. 常见问题对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动报 `DATABASE_URL is required` | 未 export 或 DSN 为空 | `set -a; . ./.env.local; set +a` |
| 启动报 `LLM_BASE_URL and LLM_MODEL are required` | 两个变量至少缺一个 | 补齐 |
| 启动报 `PORT must be between 1 and 65535` 等 | 数值/布尔/duration 格式错 | 按提示修正；duration 用 `10s`、`30m` |
| 前端地图显示「未配置 VITE_AMAP_JS_KEY」 | Vite 没读到变量 | 建 `web/.env.local`，或同 shell 先 export 再 `npm run dev` |
| 地图显示但底图空白 | JS key 白名单/安全密钥不匹配 | 检查域名白名单与 security code |
| 行程能生成但没有实时 POI/路程是直线 | `AMAP_WEB_KEY` 为空 | 填后端 Web 服务 key 后重启 |
| `/api/eval/*` 一直 401 | `ADMIN_TOKEN` 为空或不匹配 | 设置 token；请求头用 `X-Admin-Token` |
| `plugins.hotels.disabled_reason=hotel tool health check failed` | sidecar 未启动、URL 错、1s 内健康检查失败 | 先起 sidecar，确认 `curl 127.0.0.1:8090/healthz` |
| `plugins.guides.disabled_reason=GUIDE_SEARCH_API_KEY is empty` | 开关开了但没 key | 填 key；接口路径固定为 `/v1/tools/search` |
| 启动日志出现 `research plugin disabled ... get_weather ... AMAP_WEB_KEY is empty` | 未配置后端高德 key | 填 `AMAP_WEB_KEY` 后重启；`/api/meta` 的 `plugins.weather.enabled` 也会是 `false` |
| `WEATHER_*` 改了不生效 | 值为空导致默认值生效，或格式错误启动失败 | duration 用 `30m`/`3s`；`WEATHER_MAX_CALLS_PER_RUN` 取 1–10 |
| `source .env.local` 报某个单词 `command not found` | 含空格的值没加引号 | 写成 `OIDC_SCOPES="openid profile email"`，或直接以 `.env.example` 为模板 |
| Compose 起来配置仍是旧值 | 改的是根 `.env.local` | 改 `deploy/.env` 并重建 |
| 修改了 VITE key 但页面没变 | Vite 变量构建期固化 | 重启 dev server 或重新 `--build` |
| run 进入 failed，错误含 401/404 模型 | `LLM_API_KEY` 错或 `LLM_MODEL` 不存在 | 对齐 provider 的模型名与 key |
| 调整请求不会重新查酒店/攻略 | 设计如此 | 换酒店用 `/replan` 或新建行程 |
| 开启登录后启动报 `OIDC_ISSUER is required` 等 | 四个 OIDC 必填项缺一 | 补齐 issuer/client id/secret/redirect URI |
| 登录后回调报 `login_state_invalid` | state 过期、绑定 Cookie 丢失或重复回调 | 重新点击登录；跨域时检查 `credentials` 与 CORS |
| 登录失败，日志 `auth callback access token ... expected audience` | `OIDC_AUDIENCE` 填了 client id 或应用名，而 access token 的 `aud` 是资源标识 | 留空，或填 token 实际 `aud`（yufu 形如 `urn:yufu:<project-id>:<env>:api`）后重启 |
| 浏览器未能带上会话 Cookie | 分离部署缺少 CORS 或 Secure/SameSite 不匹配 | 配置 `CORS_ALLOWED_ORIGINS`，HTTPS 下保持 `AUTH_COOKIE_SECURE=auto` |
| 登录成功但行程列表为空 | 旧无主数据在登录启用后不展示，或登录的是另一个账号 | 用原账号登录；确认无需迁移旧 demo 数据 |
| 普通用户访问 `/api/eval/*` 返回 403 | 只在 `ADMIN_EMAILS`/`ADMIN_SUBS` 中才是 admin | 加入白名单后重新登录以同步角色 |
| 开启登录后 POST 返回 `403 请求来源不被允许` | Vite 代理改写了 Host，Origin 与 Host 不同源 | API 进程设置 `CORS_ALLOWED_ORIGINS=http://localhost:5173`（换成实际 Web 源） |
| IdP 退出后仍能访问 | 只清了本地会话，IdP 未配置 end-session | 配置 `OIDC_POST_LOGOUT_REDIRECT_URI` 并使用 IdP 退出 |

## 7. 安全要求

- 真实密钥只放在 `.env.local` / `deploy/.env`，两者都已 gitignore；共享文档与截图里不要出现 key。
- 服务端密钥（`LLM_API_KEY`、`AMAP_WEB_KEY`、`ADMIN_TOKEN`、`HOTEL_TOOL_TOKEN`、`FLYAI_API_KEY`、`GUIDE_SEARCH_API_KEY`、`OIDC_CLIENT_SECRET`）不得出现在任何 `VITE_*` 变量中。
- `OIDC_CLIENT_SECRET` 只放服务端环境变量，不写数据库、不下发浏览器、不写日志。
- IdP 的 access token / ID token 只用于服务端换取用户信息，浏览器只保存不透明会话 Cookie。
- `ADMIN_TOKEN` 用随机长串；空值不是「免鉴权」，而是全部拒绝。
- `HOTEL_TOOL_TOKEN` 为空时 sidecar 不鉴权，只应部署在 Compose 内网或本机回环。
- 轮换 key 后需重启 API；前端 key 还需重新构建。
