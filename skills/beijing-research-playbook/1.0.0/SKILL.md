# 北京行程研究清单

只在研究阶段使用。它补充方法，不覆盖用户约束、候选集和确定性校验。

## 1. 先确定硬信息

- 先看候选地点已有的营业时间、闭馆日和票价；没有数据时不要假设开放。
- 博物馆与展馆默认周一闭馆，除非候选数据明确写了其他规则。
- 同一天的点位尽量放在同一区域，跨区移动超过 45 分钟时在 notes 里提示。
- 用户给出预算时，优先保留免费或低价点位，把付费项目集中到用户最在意的主题。

## 2. 再用攻略补软信息

- 攻略只用来补充排队、入口、最佳时段和避坑经验，不用来决定必去点。
- 同一地点被多篇攻略提及时，提高它的 guide weight，但仍必须来自候选集。
- 攻略中的临时活动、价格和营业时间不可信，必要时在 warnings 中提醒用户出发前复核。
- 引用只使用工具返回的 http/https 地址，每个地点最多保留 3 条。

## 3. 住宿与预算

- 用户没有提住宿时，不主动推荐酒店，也不把住宿费塞进预算。
- 用户指定酒店时，把它当作每天起终点；找不到确认信息就追问，不要编造房价。
- 房价未知时标记 price_estimated，并说明是否计入预算。

## 4. 出行前检查

- 雨天备选优先选室内展馆，其次选同一区域可快速替换的点位。
- 每天至少留出 30 分钟机动时间；带老人或孩子时把步行时间按 1.2 倍估算。
- 最终输出前自查：必去点是否齐全、闭馆日是否冲突、预算是否超限、是否出现候选集之外的地点。

违反硬约束时宁可把状态标为 degraded，也不要用攻略里的说法掩盖冲突。
